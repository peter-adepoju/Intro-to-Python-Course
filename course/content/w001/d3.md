## Warm-up

:::predict
print(2 + 3 * 2)
print(7 // 2 * 2 + 7 % 2)
:::

The second one is a neat fact: for any whole numbers, `a // b * b + a % b` gives back `a`. Use the stepper from yesterday in your head: `7 // 2` is 3, times 2 is 6, plus `7 % 2` (1) is 7.

## Why we need variables

Yesterday's challenge used `10000` over and over. If the film were 9000 seconds long, you'd have to change it in five places, and you'd probably miss one. Variables fix this.

:::example title="With a variable"
seconds = 10000
print(seconds // 3600, "hours")
print(seconds % 3600 // 60, "minutes")
print(seconds % 60, "seconds")
:::

Change `10000` to `9000` on line 1 and run again. One change, and every line follows.

## How assignment works

```python
seconds = 10000
```

This is an **assignment statement**. Read it as "**seconds** is now **10000**", or "let seconds refer to 10000". It is *not* a maths equation: `=` in Python is an instruction, not a statement of fact.

What Python does, in this order:

1. Work out the value on the **right** of `=`.
2. Make the **name** on the left refer to that value.

Press **X-ray** and step through. Watch the Names column on the left and the Objects column on the right, and the arrows between them.

:::example title="X-ray me"
price = 1200
quantity = 3
total = price * quantity
print(total)
:::

On the third line, Python first looks up `price` and `quantity`, multiplies them, and *then* creates the name `total`. Because the right side is always worked out first, a name must exist before you use it:

:::example error=yes
print(score)
score = 10
:::

Python runs top to bottom, so on line 1 `score` doesn't exist yet: `NameError`. Swapping the two lines fixes it.

## Names point at objects

There's a common way to picture variables: as boxes with a name on the front, and a value inside. It's a nice picture, but it's not how Python works, and it will mislead you later (badly, in Week 8, when you meet lists).

In Python, **values are objects** that live in memory, and **a variable is a name that points at an object**, like a label tied to it with string. Assignment ties the label on. Step through both pictures side by side:

:::widget labels caption="The same three lines, two mental models. Step through, and watch what happens to y when x changes. Then try the swap and score scenarios."
{"scenario": "copy"}
:::

The key moment is `y = x`. Python does **not** copy anything. It ties a second label, `y`, onto the very same object `x` points at. Then `x = 7` moves the `x` label to a new object. `y` still points at 5.

See it in the real X-ray too:

:::example title="Two names, one object"
x = 5
y = x
x = 7
print(x, y)
:::

:::key
`=` never copies a value. It makes a name point at an object. Two names can point at the same object.
:::

You can check whether two names point at the same object with `is`, and see an object's identity (a number that's unique while it exists) with `id()`:

:::example
a = 1000
b = a
print(a is b)
print(id(a) == id(b))
:::

You won't need `is` and `id()` much yet. They'll matter in Week 8.

## Changing a variable

A variable can point at a different value later. A very common pattern is to update a variable using its own current value:

:::example title="Keeping score"
score = 0
score = score + 10
score = score + 5
print(score)
:::

`score = score + 10` makes no sense as maths, but perfect sense as an instruction: work out `score + 10` (using the *current* score), then make `score` point at the result. X-ray it and watch the arrow move each time.

:::predict
lives = 3
lives = lives - 1
lives = lives - 1
print(lives)
:::

### Shortcut operators

Updating a variable is so common that Python has shortcuts:

| Shortcut | Means |
|---|---|
| `x += 5` | `x = x + 5` |
| `x -= 2` | `x = x - 2` |
| `x *= 3` | `x = x * 3` |
| `x /= 4` | `x = x / 4` |
| `x //= 4` | `x = x // 4` |
| `x %= 4` | `x = x % 4` |
| `x **= 2` | `x = x ** 2` |

:::predict
n = 10
n += 5
n *= 2
n //= 4
print(n)
:::

:::mistake
`x =+ 5` is not a shortcut. It's `x = +5`: it sets x to positive 5. The operator goes *before* the `=`: `x += 5`.
:::

## Several names at once

You can give several names values in one line. The right side is worked out completely first, then the names are assigned left to right.

:::example
width, height = 12, 5
print(width * height)
:::

This makes **swapping** two variables easy. Without it, you'd need a temporary third variable:

:::example title="Swapping, the long way"
a = "red"
b = "blue"
temp = a
a = b
b = temp
print(a, b)
:::

:::example title="Swapping, the Python way"
a = "red"
b = "blue"
a, b = b, a
print(a, b)
:::

X-ray the second version. On line 3, Python first builds the pair `("blue", "red")` from the right side, then points `a` and `b` at them. Nothing is lost.

You can also point several names at the same value: `x = y = 0`.

## Variables don't have types, values do

A variable can point at an int now and a string later. The *value* has a type; the name doesn't care.

:::example
thing = 42
print(type(thing))
thing = "forty-two"
print(type(thing))
:::

This is called **dynamic typing**. It's convenient, but it means *you* must keep track of what each name refers to. Good names help enormously.

## Naming things well

Variable names have rules (Python enforces them) and conventions (programmers follow them).

**Rules:**

- Letters, digits and underscores only. No spaces, no hyphens.
- Can't start with a digit.
- Can't be a **keyword**: one of Python's reserved words like `if`, `for`, `class`, `True`.
- Capitals matter: `score`, `Score` and `SCORE` are three different names.

**Conventions:**

- Use `lower_case_with_underscores` (called *snake_case*): `total_price`, `num_students`.
- Say what it means: `seconds_per_day` beats `x` or `spd`.
- Don't reuse the names of built-in functions like `print`, `type`, `list`, `sum`, `max`. Python allows it, but then the built-in stops working.

Try some names. The checker uses Python's own rules:

:::widget namecheck caption="Type a name and Python checks it. Try the examples: some fail, some are allowed but unwise."
{}
:::

Here's what happens when you reuse a built-in name:

:::example error=yes nb_after="del print"
print = 5
print("hello")
:::

After line 1, `print` points at the number 5, so `print("hello")` tries to call a number. (If this happens to you in a console, press Reset.)

## Tracing by hand

**Tracing** means going through a program line by line, on paper, writing down the value of every variable after each line. It's the single best way to understand code you didn't write, and to find bugs in code you did. Professionals do it all the time, in their heads.

Draw a table with one column per variable and one row per line. For this program:

```python
a = 4
b = a * 2
a = a + b
b = b - 1
```

| After line | a | b |
|---|---|---|
| 1 | 4 | (none) |
| 2 | 4 | 8 |
| 3 | 12 | 8 |
| 4 | 12 | 7 |

Now trace these yourself on paper *before* running them. Then check with X-ray.

:::predict
x = 3
y = x + 1
x = y * 2
y = x - y
print(x, y)
:::

:::predict
p = 10
q = 3
p, q = q, p % q
print(p, q)
:::

## Quiz

:::quiz id=quiz
- q: What does `=` do in `x = 5`?
  options:
    - "Checks whether x equals 5"
    - "Makes the name x refer to the value 5"
    - "Copies 5 into a box called x"
    - "Prints 5"
  answer: 1
  explain: "Assignment ties a name to a value. It isn't a comparison (that's ==, on Week 2)."
- q: What does this print?
  type: output
  code: |
    a = 5
    b = a
    a = 9
    print(b)
  answer: "5"
  explain: "b = a ties b to the object 5. Moving a later doesn't move b."
- q: What does this print?
  type: output
  code: |
    n = 4
    n += n
    n *= 3
    print(n)
  answer: "24"
  explain: "n becomes 8, then 24."
- q: Which is a valid variable name?
  options: ["`2fast`", "`my-score`", "`my_score`", "`class`"]
  answer: 2
  explain: "No digit at the start, no hyphens, no keywords."
- q: What error does `print(x)` give if `x` was never assigned?
  type: text
  answer: ["NameError", "name error"]
  explain: "Python can't find the name."
- q: What does this print?
  type: output
  code: |
    a, b = 3, 4
    a, b = b, a + b
    print(a, b)
  answer: "4 7"
  explain: "The right side (4, 3 + 4) is worked out first using the old values."
- q: "After `x = y = 10`, how many objects are the two names pointing at?"
  options: ["One", "Two", "None"]
  answer: 0
  explain: "Both names point at the same object."
- q: What's wrong with `total =+ 5`?
  options:
    - "Nothing, it adds 5"
    - "It's a SyntaxError"
    - "It sets total to +5 instead of adding 5"
    - "It subtracts 5"
  answer: 2
  explain: "It's read as total = (+5). The shortcut is +=."
- q: Why is `sum = 10` a bad idea?
  options:
    - "It's a SyntaxError"
    - "sum is a built-in function, and this hides it"
    - "Variables can't hold 10"
  answer: 1
  explain: "It's allowed, but afterwards sum(...) no longer works in that program."
- q: What is the type of `x` after `x = 7` then `x = x / 7`?
  options: ["int", "float", "str"]
  answer: 1
  explain: "/ always produces a float, so x now refers to 1.0."
:::

## Daily challenge

:::exercise id=challenge points=20 title="Challenge: three-way rotate"
Three variables hold three colours. Rotate them so each one gets the value of the next (`first` gets `second`'s value, `second` gets `third`'s, `third` gets `first`'s) in a **single** line. Then print them: `green blue red`.

Stretch goal, in your head: how would you do it without the one-line trick, and how many temporary variables would you need?
@@starter
first = "red"
second = "green"
third = "blue"
# one line here
print(first, second, third)
@@tests
def test_output():
    "prints green blue red"
    expect_output("green blue red")
def test_one_line():
    "rotates in one assignment"
    import re
    assert re.search(r"^\s*first\s*,\s*second\s*,\s*third\s*=", source, re.M), "Do the rotation with one multiple assignment: first, second, third = ..."
@@solution

second = "green"
third = "blue"
first, second, third = second, third, first
print(first, second, third)
:::
