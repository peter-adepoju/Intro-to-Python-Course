## Warm-up

:::predict
x = len("hello")
y = len("hi") * 10
print(x + y)
print(len("abc") + len("de"))
:::

`len` doesn't print anything. It works out a number and **gives it back**, so you can store it, do sums with it, or pass it to another function. Your functions can do the same.

## return: handing a value back

:::example
def area(width, height):
    return width * height

a = area(7, 4)
print(a)
print(area(2, 3) + area(10, 10))
print("Big" if area(50, 50) > 2000 else "Small")
:::

`return width * height` does two things: it works out the value, and it ends the function, handing that value back to wherever the function was called. The call `area(7, 4)` **becomes** that value, just as `len("hello")` becomes 5.

Press X-ray and watch the moment `return` runs: the frame disappears and the call is replaced by the returned value, which is then stored in `a`.

:::key
A call to a function that returns a value is an **expression**: it has a value, so it can go anywhere a value can. Store it, print it, compare it, or pass it to another function.
:::

Because calls are expressions, functions combine naturally:

:::example
def square(n):
    return n * n

def add(a, b):
    return a + b

print(add(square(3), square(4)))
print(square(square(2)))
:::

`add(square(3), square(4))` works from the inside out, just like `int(input())`: both `square` calls run first, then `add` runs with their results.

## print is not return

This is the most important idea of the day. `print` and `return` can look as if they do the same thing, because in a small test both make a number appear. They're completely different:

- `print` shows a value **to a person**, on the screen. The program can't use what was printed.
- `return` hands a value **to the program**. Nothing appears on screen unless the program decides to print it.

Here are two functions that look almost identical:

:::example
def double_print(n):
    print(n * 2)

def double_return(n):
    return n * 2

double_print(5)
double_return(5)
print("---")
a = double_print(5)
b = double_return(5)
print(a, b)
:::

Line by line: `double_print(5)` shows 10. `double_return(5)` shows nothing, because the returned 10 isn't used. Then `a = double_print(5)` shows 10 **again**, and stores... what? The last line reveals it: `None`.

### None

A function without a `return` (or with a bare `return`) gives back a special value, **`None`**, which means "no value". It has its own type, `NoneType`, and it's falsy.

:::example
def nothing():
    pass

result = nothing()
print(result)
print(type(result))
print(result is None)
:::

To check for `None`, write `x is None`. (`is` asks whether two names point at the very same object, and there is only ever one `None` object.)

The classic bug: using a printing function as if it returned something.

:::example error=yes title="The classic bug"
def add_vat(price):
    print(price * 1.075)

total = add_vat(1000) + add_vat(500)
:::

`add_vat(1000)` prints 1075.0 and returns `None`. Then Python tries `None + None` and raises `TypeError: unsupported operand type(s) for +: 'NoneType' and 'NoneType'`. Whenever you see `NoneType` in an error, look for a function that printed when it should have returned.

:::tip
Most functions should **return** their results and let the caller decide what to do with them: print them, store them, test them. Keep `print` for functions whose whole job is showing something, like a menu or a report.
:::

## return ends the function

The moment `return` runs, the function is over. Any lines after it are skipped. That makes `return` great for handling special cases first:

:::example title="Early return"
def safe_divide(a, b):
    if b == 0:
        return 0
    return a / b

print(safe_divide(10, 4))
print(safe_divide(10, 0))
:::

A function can have several `return` statements, one per branch:

:::example
def grade(mark):
    if mark >= 70:
        return "A"
    if mark >= 60:
        return "B"
    if mark >= 50:
        return "C"
    return "F"

print(grade(85), grade(65), grade(12))
:::

Notice there's no `elif` and no `else`: once a `return` runs, nothing below it runs, so each `if` only gets checked if all the earlier ones were false.

:::mistake title="A path with no return"
If one path through a function has no `return`, that path returns `None`:

```python
def sign(n):
    if n > 0:
        return "positive"
    elif n < 0:
        return "negative"
    # n == 0 falls off the end, and the function returns None
```
:::

### return from inside a loop

`return` doesn't just leave the loop like `break`: it leaves the whole function. That makes search functions wonderfully simple. Compare the prime test from Week 3, with its flag and its `while ... else`, with this:

:::example title="A prime test as a function"
def is_prime(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True

for k in range(1, 30):
    if is_prime(k):
        print(k, end=" ")
:::

As soon as a divisor is found, the answer is known: `return False`. If the loop finishes without finding one, the last line says so. No flag, no `break`, no `else`.

:::example title="Find first, as a function"
def first_vowel(word):
    for i in range(len(word)):
        if word[i] in "aeiou":
            return i
    return -1

print(first_vowel("python"), first_vowel("rhythm"))
:::

## Functions that answer yes or no

Functions that return `True` or `False` are called **predicates**, and they're usually named like questions: `is_prime`, `is_even`, `has_digit`, `can_vote`. They read beautifully in conditions:

:::example
def is_even(n):
    return n % 2 == 0

def is_leap(year):
    return (year % 4 == 0 and year % 100 != 0) or year % 400 == 0

if is_leap(2024) and is_even(2024):
    print("2024 is an even leap year")
:::

Notice `return n % 2 == 0`: the comparison already **is** `True` or `False`, so there's no need for `if ... return True else return False`.

## Returning several values

A function can return several values, separated by commas. The caller unpacks them, just as you did with `a, b = b, a`:

:::example
def min_sec(total_seconds):
    return total_seconds // 60, total_seconds % 60

m, s = min_sec(754)
print(f"{m} min {s} s")
:::

(Strictly, the function returns one value: a **tuple** holding both numbers. You'll learn about tuples in Week 9.)

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: Goldbach, properly"
Remember the Goldbach challenge from Week 3, with the prime test written out twice? Now do it properly.

1. Define `is_prime(n)`.
2. Define `goldbach(n)` that **returns** the pair of primes `p, q` with `p <= q`, `p + q == n` and the smallest possible `p`, for any even `n` greater than 2.
3. Define `count_pairs(n)` that returns how many pairs `p <= q` of primes add up to `n`.
4. Ask for an even number with the prompt `Even number: ` and print `28 = 5 + 23`, then `Pairs: 2`.
@@starter

@@tests
def P(n):
    return n > 1 and all(n % d for d in range(2, int(n ** 0.5) + 1))
def test_goldbach():
    "goldbach returns the first pair"
    for n in [4, 28, 100, 98, 1000]:
        p = next(k for k in range(2, n) if P(k) and P(n - k))
        assert tuple(goldbach(n)) == (p, n - p), f"goldbach({n}) should return {(p, n - p)}."
def test_count():
    "count_pairs counts every pair once"
    for n in [4, 10, 28, 100]:
        want = sum(1 for p in range(2, n // 2 + 1) if P(p) and P(n - p))
        assert count_pairs(n) == want, f"count_pairs({n}) should be {want}."
def test_output():
    "the printed lines"
    expect_output("Even number: 28\n28 = 5 + 23\nPairs: 2", inputs=["28"], echo=True)
@@hint
Inside `goldbach`, loop `p` from 2 and `return p, n - p` as soon as both are prime.
@@hint
In `count_pairs`, `p` only needs to go up to `n // 2`, so that each pair is counted once.
@@solution
def is_prime(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True

def goldbach(n):
    for p in range(2, n):
        if is_prime(p) and is_prime(n - p):
            return p, n - p

def count_pairs(n):
    count = 0
    for p in range(2, n // 2 + 1):
        if is_prime(p) and is_prime(n - p):
            count += 1
    return count

n = int(input("Even number: "))
p, q = goldbach(n)
print(f"{n} = {p} + {q}")
print("Pairs:", count_pairs(n))
:::
