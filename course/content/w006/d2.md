## Warm-up

:::predict
print("a", "b", "c", sep="-", end="!\n")
print("x", end="")
print("y")
:::

`sep` and `end` are **parameters** of `print`, with default values (a space and a new line) that you override by naming them. By the end of today you'll be able to write functions that work exactly like this.

## Several parameters

A function can have as many parameters as it needs, separated by commas. The arguments in a call are matched to the parameters **by position**: the first argument to the first parameter, the second to the second, and so on.

:::example
def rectangle(width, height):
    print("Area:", width * height)
    print("Perimeter:", 2 * (width + height))

rectangle(7, 4)
rectangle(2, 10)
:::

Because matching is by position, **order matters**. Get it wrong and the function silently does the wrong thing:

:::example
def introduce(name, age):
    print(f"{name} is {age} years old.")

introduce("Ada", 36)
introduce(36, "Ada")
:::

The second call runs without an error, but it's nonsense. Python can't know you meant the other order.

### The wrong number of arguments

If the number of arguments doesn't match, Python refuses before the body runs, and the error says exactly what's wrong:

:::example error=yes
def rectangle(width, height):
    print(width * height)

rectangle(7)
:::

:::example error=yes
def rectangle(width, height):
    print(width * height)

rectangle(7, 4, 2)
:::

`missing 1 required positional argument: 'height'` and `takes 2 positional arguments but 3 were given`. Read these messages carefully: they name the function and the parameter.

### Arguments can be any expression

Each argument is worked out **before** the function is called, and the parameter points at the result:

:::example
def show_total(amount):
    print(f"Total: {amount:,}")

price = 2500
show_total(price * 3 + 500)
show_total(len("abc") * 1000)
:::

## Keyword arguments

You can also name the parameter in the call: `parameter=value`. These are **keyword arguments**, and with them the order doesn't matter:

:::example
def introduce(name, age):
    print(f"{name} is {age} years old.")

introduce(name="Ada", age=36)
introduce(age=36, name="Ada")
:::

Keyword arguments make calls easier to read, especially when a function has several parameters of the same type:

```python
book_room("Lagos", 3, 2)                          # what do 3 and 2 mean?
book_room(city="Lagos", nights=3, guests=2)       # clear
```

You can mix the two, but **positional arguments must come first**:

:::example
def introduce(name, age):
    print(f"{name} is {age} years old.")

introduce("Ada", age=36)
:::

:::example error=yes
def introduce(name, age):
    print(f"{name} is {age} years old.")

introduce(name="Ada", 36)
:::

That's a `SyntaxError`: once you've named one argument, Python can't tell which parameter a following unnamed one is for.

## Default values

A parameter can have a **default value**, written `parameter=value` in the `def`. If the call doesn't give that argument, the default is used:

:::example
def greet(name, greeting="Hello"):
    print(f"{greeting}, {name}!")

greet("Ada")
greet("Ada", "Good morning")
greet("Ada", greeting="Hi")
:::

Defaults make a function easy to use in the common case, and flexible in the unusual one. That's exactly what `print` does with `sep` and `end`.

:::example title="A flexible line"
def line(length=20, char="-"):
    print(char * length)

line()
line(10)
line(char="=")
line(5, "*")
:::

### Defaults must come last

Parameters with defaults must come **after** those without:

:::example error=yes
def greet(greeting="Hello", name):
    print(greeting, name)
:::

Think about why: in `greet("Ada")`, would `"Ada"` be the greeting or the name? Python avoids the question by not allowing it.

:::key
Positional arguments are matched in order. Keyword arguments are matched by name and must come after positional ones. Parameters with defaults can be left out of the call, and must come after parameters without defaults.
:::

:::warn
Use only simple, unchangeable values as defaults: numbers, strings, `True`, `False`. In Week 8 you'll see why a default like an empty list causes a famous bug.
:::

## Parameters are local labels

When a function is called, each parameter is a new name, inside the function's frame, pointing at the argument's object. Exactly as in Week 1, Day 3: names are labels.

So what happens if the function points its parameter at something else?

:::example title="X-ray this"
def add_tax(price):
    price = price * 1.075
    print("Inside:", price)

cost = 1000
add_tax(cost)
print("Outside:", cost)
:::

Step through it in X-ray. At the call, `price` in the function's frame points at the same object as `cost`: the number 1000. Then `price = price * 1.075` moves the label `price` to a **new** object. `cost`, in the main frame, still points at 1000. Reassigning a parameter never changes the caller's variable.

To get a value back out of a function, you need `return`, which is tomorrow's lesson.

:::note
Numbers and strings can't be changed, so this is the whole story for them. Lists can be changed in place, and then a function **can** affect the caller's data through a parameter. You'll see that, and how to control it, in Week 8.
:::

    out = ""
    for i in range(times):

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: the banner"
Define `banner(text, width=30, char="=", align="centre")` that prints three lines: a line of `char` of length `width`, the text aligned inside that width, and the line again. `align` can be `"left"`, `"centre"` or `"right"`. If the text is longer than the width, the width grows to fit it.

Then make these calls:

```python
banner("Python Atlas")
banner("Week 6", width=12, char="*", align="left")
banner("Functions", align="right", char="-")
banner("A title that is far too long for the box", width=10)
```
@@starter

@@tests
def b(t, w=30, c="=", a="centre"):
    w = max(w, len(t))
    mid = t.center(w) if a == "centre" else t.ljust(w) if a == "left" else t.rjust(w)
    return c * w + "\n" + mid + "\n" + c * w
def test_output():
    "four banners"
    expect_output("\n".join([b("Python Atlas"), b("Week 6", 12, "*", "left"), b("Functions", a="right", c="-"), b("A title that is far too long for the box", 10)]))
def test_defaults():
    "the defaults"
    assert banner.__defaults__ == (30, "=", "centre"), "Use the defaults width=30, char='=', align='centre'."
@@hint
`max(width, len(text))` makes the width grow. Then choose `.ljust`, `.center` or `.rjust` (or an f-string with `<`, `^` or `>`) depending on `align`.
@@solution
def banner(text, width=30, char="=", align="centre"):
    width = max(width, len(text))
    if align == "left":
        middle = text.ljust(width)
    elif align == "right":
        middle = text.rjust(width)
    else:
        middle = text.center(width)
    print(char * width)
    print(middle)
    print(char * width)

banner("Python Atlas")
banner("Week 6", width=12, char="*", align="left")
banner("Functions", align="right", char="-")
banner("A title that is far too long for the box", width=10)
:::
