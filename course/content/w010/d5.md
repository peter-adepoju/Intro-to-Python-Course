## Warm-up

:::predict
visitors = ["Ada", "Bo", "Ada", "Cy", "Bo", "Ada"]
unique = []
for v in visitors:
    if v not in unique:
        unique.append(v)
print(unique, len(unique))
:::

That loop removes duplicates by checking each name against everything kept so far. It works, but `v not in unique` looks through the whole list each time. With a million visitors, that's very slow. A set does the same job in one step, however big it is.

## What a set is

A **set** is an unordered collection of **unique** elements, written in curly brackets without colons:

:::example
colours = {"red", "green", "blue", "red"}
print(colours)
print(len(colours))
print("green" in colours)
:::

The second `"red"` vanished: a set holds each element once. And the order you see may differ from the order you typed. A set has **no order**, so there's no indexing and no slicing: `colours[0]` is a `TypeError`.

`set(...)` makes a set from any sequence, which is the quickest way to remove duplicates:

:::example
visitors = ["Ada", "Bo", "Ada", "Cy", "Bo", "Ada"]
print(len(set(visitors)))
print(set("mississippi"))
print(sorted(set(visitors)))
:::

`sorted` gives a list back, in order, which is the usual way to display a set.

### The empty set

`{}` is an empty **dictionary**. An empty set has to be written `set()`:

:::example
a = {}
b = set()
print(type(a), type(b))
:::

### What can be in a set

Elements follow the same rule as dictionary keys: they must be **hashable** (strings, numbers, tuples, not lists or dictionaries). That isn't a coincidence. A set works like a dictionary's keys: Python stores each element at a place worked out from its hash, so checking whether something is there doesn't need a search.

:::example error=yes
s = {[1, 2], [3]}
:::

:::key
A set holds unique, hashable elements in no particular order. `x in s` takes about the same time whatever the size of the set. Use a set when you care **whether** something is there, not **where** or **how many times**.
:::

## Changing a set

Sets are mutable. `add` adds one element (nothing happens if it's already there); `update` adds every element of a sequence:

:::example
seen = set()
seen.add("Ada")
seen.add("Bo")
seen.add("Ada")
seen.update(["Cy", "Di"])
print(sorted(seen))
:::

There are two ways to remove an element. `remove` raises a `KeyError` if it isn't there; `discard` quietly does nothing:

:::example
s = {"Ada", "Bo"}
s.discard("Zed")
s.remove("Bo")
print(s)
:::

`pop` removes and returns an arbitrary element, and `clear` empties the set.

### The "seen" pattern

The most common use of a set in a loop is remembering what you've already met:

:::example title="First repeated word"
words = "the quick fox saw the lazy dog".split()
seen = set()
for w in words:
    if w in seen:
        print("First repeat:", w)
        break
    seen.add(w)
:::

:::example title="Remove duplicates, keeping the order"
visitors = ["Ada", "Bo", "Ada", "Cy", "Bo"]
seen = set()
unique = []
for v in visitors:
    if v not in seen:
        seen.add(v)
        unique.append(v)
print(unique)
:::

`set(visitors)` loses the order; this keeps the first appearance of each, and stays fast because the check is against the set.

## Set operations

The real power of sets is combining them. Suppose `a` and `b` are the students taking two subjects:

- `a | b`, the **union**: students in either (or both);
- `a & b`, the **intersection**: students in both;
- `a - b`, the **difference**: in `a` but not in `b`;
- `a ^ b`, the **symmetric difference**: in exactly one of them.

:::widget setvenn caption="Pick an operation to shade the regions it keeps. Edit the sets: try adding a name to both, or the same name twice."
:::

:::example
maths = {"Ada", "Bo", "Cy", "Di"}
physics = {"Cy", "Di", "Ed"}
print(sorted(maths | physics))
print(sorted(maths & physics))
print(sorted(maths - physics))
print(sorted(maths ^ physics))
:::

Each operator makes a **new** set. There are method versions too, `a.union(b)`, `a.intersection(b)`, `a.difference(b)` and `a.symmetric_difference(b)`, which accept any sequence, not just a set:

:::example
maths = {"Ada", "Bo", "Cy"}
print(sorted(maths.intersection(["Bo", "Cy", "Zed"])))
:::

And there are versions that change a set in place: `a |= b`, `a &= b`, `a -= b`.

:::example title="Letters in common"
a, b = "python", "typhoon"
print(sorted(set(a) & set(b)))
print(sorted(set(a) - set(b)))
:::

## Comparing sets

Two sets are equal when they hold the same elements, whatever order you wrote them in:

:::example
print({1, 2, 3} == {3, 2, 1})
print([1, 2, 3] == [3, 2, 1])
:::

`a <= b` asks whether `a` is a **subset** of `b` (every element of `a` is in `b`); `a >= b` asks whether it's a **superset**. `a.isdisjoint(b)` asks whether they have **nothing** in common.

:::example
required = {"name", "email"}
form = {"name", "email", "phone"}
print(required <= form)
print({"admin"}.isdisjoint(form))
:::

### Frozen sets

A set can't be an element of another set, or a dictionary key, because it's mutable. A `frozenset` is a set that can't be changed, so it can:

:::example
pairs = {frozenset({"Ada", "Bo"}), frozenset({"Bo", "Ada"})}
print(len(pairs))
:::

The two frozensets are equal (order doesn't matter), so the outer set keeps one. That's a neat way to treat `("Ada", "Bo")` and `("Bo", "Ada")` as the same pair.

## Choosing a collection

You now know the four built-in collections. Choose by what you need to do:

| Collection | Ordered? | Duplicates? | Changeable? | Use it for |
|---|---|---|---|---|
| list `[...]` | yes | yes | yes | a sequence of things, in order |
| tuple `(...)` | yes | yes | no | a fixed group of values, a record, a key |
| dict `{k: v}` | by insertion | keys unique | yes | looking up a value by a key |
| set `{...}` | no | no | yes | membership, removing duplicates, comparing groups |

Speed matters too. Here's the difference for `in`:

:::example
import time
n = 10_000
as_list = list(range(n))
as_set = set(as_list)
start = time.perf_counter()
for x in range(0, n, 10):
    x in as_list
middle = time.perf_counter()
for x in range(0, n, 10):
    x in as_set
end = time.perf_counter()
print(f"list: {middle - start:.4f} s")
print(f"set:  {end - middle:.6f} s")
:::

The exact times depend on your computer, but the set is usually hundreds of times faster, and the gap grows with the size. You'll learn to measure and reason about this properly in Phase 2.

:::mistake
Don't use a list for frequent "is it in here?" checks on large data, and don't use a set when the order or the count matters. Turning a list into a set throws away both.
:::

:::exercise id=first_dup points=10 title="First repeat"

@@starter

@@tests

    "several lists"

    assert first_repeat("abcdefa") == "a"
    assert first_repeat([1, 2, 3]) is None
    assert "set(" in source
@@solution
def first_repeat(items):
    seen = set()
    for x in items:
        if x in seen:
            return x
        seen.add(x)
    return None

:::exercise id=only_one points=10 title="In exactly one"
Write `exactly_one(a, b, c)` that returns, sorted, the elements that appear in exactly one of three lists.
@@starter

@@tests
def test_values():
    "several lists"
    assert exactly_one([1, 2, 3], [2, 4], [3, 4, 5]) == [1, 5]
    assert exactly_one([], [], [7]) == [7]
    assert exactly_one([1], [1], [1]) == []
@@hint
`a ^ b ^ c` keeps elements in an odd number of the sets, which includes those in all three. Count instead, or remove the ones in all three.
@@solution
def exactly_one(a, b, c):
    a, b, c = set(a), set(b), set(c)
    return sorted((a - b - c) | (b - a - c) | (c - a - b))

:::exercise id=two_sum points=15 title="A pair that adds up"
Write `pair_sum(numbers, target)` that returns `True` if two numbers at **different** positions in the list add up to `target`. Go through the list once, keeping a set of numbers seen so far: for each number, is `target - number` in the set?
@@starter

@@tests
def test_values():
    "several lists"
    assert pair_sum([3, 9, 4, 7], 11) is True
    assert pair_sum([3, 9, 4, 7], 6) is False
    assert pair_sum([3, 3], 6) is True
    assert pair_sum([5], 10) is False
    assert pair_sum([], 0) is False
@@solution
def pair_sum(numbers, target):
    seen = set()
    for n in numbers:
        if target - n in seen:
            return True
        seen.add(n)
    return False
:::

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: friend suggestions"
A social network stores friendships as a list of pairs, like `("Ada", "Bo")`. Friendship works both ways. Write:

- `build(pairs)`: a dictionary from each person to the **set** of their friends.
- `mutual(network, a, b)`: the sorted list of friends `a` and `b` have in common.
- `suggest(network, person)`: people who aren't `person` and aren't already their friend, but are friends with at least one of their friends. Return them as a list of `(name, mutual_count)` tuples, most mutual friends first, then alphabetically.

```
pairs = [("Ada", "Bo"), ("Ada", "Cy"), ("Bo", "Di"), ("Cy", "Di"), ("Cy", "Ed"), ("Di", "Fe")]
suggest(build(pairs), "Ada")  ->  [("Di", 2), ("Ed", 1)]
```
@@starter

@@tests
PAIRS = [("Ada", "Bo"), ("Ada", "Cy"), ("Bo", "Di"), ("Cy", "Di"), ("Cy", "Ed"), ("Di", "Fe")]
def test_build():
    "build"
    n = build(PAIRS)
    assert n["Ada"] == {"Bo", "Cy"}
    assert n["Di"] == {"Bo", "Cy", "Fe"}
    assert n["Fe"] == {"Di"}
    assert build([]) == {}
def test_mutual():
    "mutual"
    n = build(PAIRS)
    assert mutual(n, "Ada", "Di") == ["Bo", "Cy"]
    assert mutual(n, "Ada", "Fe") == []
def test_suggest():
    "suggest"
    n = build(PAIRS)
    assert suggest(n, "Ada") == [("Di", 2), ("Ed", 1)]
    assert suggest(n, "Fe") == [("Bo", 1), ("Cy", 1)]
    assert suggest(build([("A", "B")]), "A") == []
@@hint
In `build`, use `setdefault(name, set()).add(friend)` for both directions of each pair.
@@hint
For `suggest`, the candidates are the union of the friends' friend sets, minus the person and minus their friends. For each candidate, the mutual count is `len(network[person] & network[candidate])`.
@@solution
def build(pairs):
    network = {}
    for a, b in pairs:
        network.setdefault(a, set()).add(b)
        network.setdefault(b, set()).add(a)
    return network

def mutual(network, a, b):
    return sorted(network[a] & network[b])

def suggest(network, person):
    friends = network[person]
    candidates = set()
    for f in friends:
        candidates |= network[f]
    candidates -= friends
    candidates.discard(person)
    scored = [(c, len(friends & network[c])) for c in candidates]
    return sorted(scored, key=lambda p: (-p[1], p[0]))
:::
