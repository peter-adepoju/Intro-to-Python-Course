## Warm-up

:::predict
for i in range(3):
    print("Row", i)
print("Done")
:::

Now imagine that each row, instead of one `print`, had to do a whole job with its own loop. That's today.

## A loop inside a loop

:::example title="Every pair of i and j"
for i in range(3):
    for j in range(4):
        print(i, j)
:::

That prints 12 lines. Here's what Python does:

1. The outer loop sets `i` to 0.
2. The inner loop runs **completely**: `j` is 0, 1, 2, 3.
3. The outer loop moves on: `i` is 1. The inner loop starts **again from the beginning**: `j` is 0, 1, 2, 3 again.
4. And once more for `i` = 2.

So the inner variable changes fastest, like the seconds on a clock, and the outer one only ticks over when the inner loop has finished, like the minutes. Step through it:

:::widget nested caption="Each cell is one run of the body; the numbers show the order. The inner loop sweeps across a row before the outer loop moves down. Tick the box to make the inner loop depend on i."
{"rows": 3, "cols": 4}
:::

:::key
In nested loops, the inner loop runs **completely** for each pass of the outer loop. If the outer loop runs `a` times and the inner one `b` times, the body runs `a × b` times.
:::

:::predict
for x in "ab":
    for y in "123":
        print(x + y, end=" ")
:::

## Shapes, row by row

Nested loops are natural for anything with **rows** and **columns**. The outer loop goes down the rows; the inner loop goes across one row.

:::example title="A rectangle"
for row in range(3):
    for col in range(8):
        print("#", end="")
    print()
:::

Look at the `print()` with nothing in it. It's inside the outer loop but **outside** the inner one, so it runs once per row, after the row is complete, to start a new line. Getting that one line's indentation right is half the battle with shapes.

### When the inner loop depends on the outer one

If the inner `range` uses the outer variable, each row can have a different length:

:::example title="A triangle"
for row in range(1, 6):
    for col in range(row):
        print("*", end="")
    print()
:::

Row 1 has one star, row 2 has two, and so on. Tick the box on the figure above to see which cells get visited.

:::example title="Numbers in a triangle"
for row in range(1, 6):
    for col in range(1, row + 1):
        print(col, end=" ")
    print()
:::

:::tip
For any shape, first write down **what row number `r` should look like**: how many spaces, how many stars, which numbers. Then the inner loop (or loops) just builds row `r`.
:::

### Shapes without the inner loop

Python's string repetition can sometimes replace the inner loop entirely:

:::example title="A centred pyramid"
height = 5
for r in range(1, height + 1):
    print(" " * (height - r) + "*" * (2 * r - 1))
:::

Row `r` has `height - r` spaces then `2r - 1` stars. Working out formulas like these is the real skill. The loop is the easy part.

## Tables and grids

A multiplication grid is a classic nested loop. Formatting every entry to the same width makes the columns line up:

:::example title="A 6 by 6 multiplication grid"
for a in range(1, 7):
    for b in range(1, 7):
        print(f"{a * b:4}", end="")
    print()
:::

### Every pair

Nested loops visit every **pair** of things. Two dice give 36 pairs:

:::example title="How many ways to roll 7 with two dice?"
ways = 0
for d1 in range(1, 7):
    for d2 in range(1, 7):
        if d1 + d2 == 7:
            ways += 1
print(ways, "ways out of 36")
:::

Sometimes you want each pair only **once**, and never a thing paired with itself. Start the inner loop just after the outer one:

:::example title="Every match in a tournament of four"
teams = "ABCD"
for i in range(len(teams)):
    for j in range(i + 1, len(teams)):
        print(teams[i], "v", teams[j])
:::

Six matches: A v B, A v C, and so on. Starting `j` at `i + 1` means B v A is never repeated, and nobody plays themselves.

## Breaking out

`break` only leaves the **innermost** loop it's in. The outer loop carries on:

:::example title="break stops only the inner loop"
for i in range(3):
    for j in range(3):
        if j == 1:
            break
        print(i, j)
:::

To stop **both** loops, set a flag before breaking, and check it in the outer loop:

:::example title="Find the first pair that multiplies to 42"
found = False
for a in range(2, 10):
    for b in range(a, 10):
        if a * b == 42:
            found = True
            break
    if found:
        break
print(a, b)
:::

(In Week 6 you'll meet a cleaner way: put the loops in a function, and `return`.)

## How much work?

Two nested loops over `n` things do `n × n` passes of the inner body. That grows fast:

| n | n × n |
|---|---|
| 10 | 100 |
| 1,000 | 1,000,000 |
| 100,000 | 10,000,000,000 |

At 100,000 things, a computer that does 100 million simple steps a second would need well over a minute. Three nested loops are `n × n × n`. When a program is mysteriously slow, look for nested loops over large things first. In Phase 2 you'll learn to describe this precisely, and to find faster ways.

:::example title="Count the work"
n = 300
steps = 0
for i in range(n):
    for j in range(n):
        steps += 1
print(steps, "passes for n =", n)
:::

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: Pythagorean triples"
A **Pythagorean triple** is three whole numbers `a < b < c` with `a² + b² = c²`, like 3, 4, 5. They give right-angled triangles with whole-number sides, and builders have used 3, 4, 5 to make square corners for thousands of years.

Ask for a limit with the prompt `Up to: ` and print every triple with `c` no bigger than the limit, one per line like `3 4 5`, in order of `a`, then `b`. Finish with `Found ` and the number of triples.
@@starter

@@tests
def triples(n):
    out = []
    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            for c in range(b + 1, n + 1):
                if a * a + b * b == c * c:
                    out.append(f"{a} {b} {c}")
    return out
def test_20():
    "up to 20"
    t = triples(20)
    expect_output("Up to: 20\n" + "\n".join(t) + f"\nFound {len(t)}", inputs=["20"], echo=True)
def test_5():
    "up to 5"
    expect_output("Up to: 5\n3 4 5\nFound 1", inputs=["5"], echo=True)
def test_4():
    "up to 4"
    expect_output("Up to: 4\nFound 0", inputs=["4"], echo=True)
@@hint
Three nested loops: `a` from 1, `b` from `a + 1`, `c` from `b + 1`, all up to the limit.
@@hint
Stretch, in your head: you don't really need the `c` loop. Given `a` and `b`, which single `c` could work? How much faster would that be?
@@solution
n = int(input("Up to: "))
found = 0
for a in range(1, n + 1):
    for b in range(a + 1, n + 1):
        for c in range(b + 1, n + 1):
            if a * a + b * b == c * c:
                print(a, b, c)
                found += 1
print("Found", found)
:::
