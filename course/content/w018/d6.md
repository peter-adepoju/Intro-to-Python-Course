Keep `lo = 0`, `hi = len(items)`. While `lo < hi`: if `items[mid] < x`, the answer is past `mid` (`lo = mid + 1`); otherwise `hi = mid`.
@@solution
def count_below(sorted_items, x):
    lo, hi = 0, len(sorted_items)
    while lo < hi:
        mid = (lo + hi) // 2
        if sorted_items[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo

:::exercise id=mix_kth points=10 title="The kth smallest"
Write `kth_smallest(items, k)` returning the kth smallest item (k = 1 is the smallest) by running only the first k rounds of selection sort on a copy. Don't use `sort`, `sorted` or `min`.
@@starter

@@tests
def test_values():
    "several"
    data = [42, 7, 19, 3, 88, 25, 11]
    assert [kth_smallest(data, k) for k in (1, 2, 3, 7)] == [3, 7, 11, 88]
    assert data == [42, 7, 19, 3, 88, 25, 11]
    assert "sorted" not in source and ".sort(" not in source and " min(" not in source
@@solution
def kth_smallest(items, k):
    items = items[:]
    for i in range(k):
        smallest = i
        for j in range(i + 1, len(items)):
            if items[j] < items[smallest]:
                smallest = j
        items[i], items[smallest] = items[smallest], items[i]
    return items[k - 1]
:::

Write `merge(a, b)` that merges two sorted lists into one sorted list in O(len(a) + len(b)), taking from `a` on ties so that it's stable. Don't use `sort` or `sorted`. (Next week, this is the heart of merge sort.)
@@starter

@@tests
def test_values():
    "several"
    assert merge([1, 4, 9], [2, 3, 10]) == [1, 2, 3, 4, 9, 10]
    assert merge([], [1]) == [1] and merge([], []) == []
    a = [(1, "a"), (3, "a")]

def merge(a, b):
    result = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    return result + a[i:] + b[j:]
:::

:::exercise id=mix_inv points=10 title="Nearly sorted?"
Write `nearly_sorted(items, limit)` returning `True` if insertion sort would make at most `limit` shifts on the list. Run insertion sort on a copy, counting shifts, and stop as soon as the count goes over `limit`, so it's fast on long lists that are far from sorted.
@@starter

@@tests
def test_values():
    "several"
    assert nearly_sorted([1, 2, 4, 3, 5], 1) is True
    assert nearly_sorted([3, 2, 1], 2) is False and nearly_sorted([3, 2, 1], 3) is True
    assert nearly_sorted([], 0) is True
    assert nearly_sorted(list(range(300_000, 0, -1)), 10) is False
@@solution
def nearly_sorted(items, limit):
    items = items[:]
    shifts = 0
    for i in range(1, len(items)):
        current = items[i]
        j = i - 1
        while j >= 0 and items[j] > current:
            items[j + 1] = items[j]
            shifts += 1
            if shifts > limit:
                return False
            j -= 1
        items[j + 1] = current
    return True
:::

## Forge: a library catalogue

A small community library keeps its books as records `(title, author, year, loans)`, where `loans` is how many times the book has been borrowed. Here is a sample:

```
BOOKS = [
    ("Things Fall Apart", "Chinua Achebe", 1958, 41),
    ("Half of a Yellow Sun", "Chimamanda Ngozi Adichie", 2006, 37),
    ("The Famished Road", "Ben Okri", 1991, 22),
    ("Purple Hibiscus", "Chimamanda Ngozi Adichie", 2003, 41),
    ("Arrow of God", "Chinua Achebe", 1964, 15),
    ("The Joys of Motherhood", "Buchi Emecheta", 1979, 22),
    ("Stay With Me", "Ayobami Adebayo", 2017, 30),
    ("The Fishermen", "Chigozie Obioma", 2015, 30),
    ("Americanah", "Chimamanda Ngozi Adichie", 2013, 52),
    ("No Longer at Ease", "Chinua Achebe", 1960, 15),
]
```

:::exercise id=forge points=50 title="Forge: a library catalogue"
Write these functions. **Don't use `sort`, `sorted`, `min`, `max` or `bisect` anywhere**: you're building them yourself.

1. `stable_sort(records, key)`: return a **new** list sorted by `key(record)`, stable, using insertion sort.
2. `catalogue(books)`: the books sorted by author (the whole name as written, A to Z), then by year (oldest first), using **two** calls to `stable_sort`.
3. `title_index(books)`: the books sorted by title, ignoring capitals.
4. `find_title(index, title)`: binary search a `title_index` list for a title (ignoring capitals); return the record or `None`.
5. `starting_with(index, prefix)`: every record in a `title_index` list whose title starts with `prefix` (ignoring capitals), in index order. Use binary search to find the first title that is not less than the prefix, then go forward while titles still start with it, so the cost is O(log n + number found).
6. `most_borrowed(books, k)`: the `k` books with the most loans, highest first; ties go to the book that comes **first** in `books`. Use `k` rounds of a selection that picks the largest, on a copy (O(kn)), making sure ties are broken by original position.
@@starter

`catalogue`: sort by year first, then by author. Both sorts are stable, so books by the same author stay in year order.
@@hint
`find_title` and `starting_with`: compare `title.lower()` values. For `starting_with`, find the first position whose title is `>=` the prefix (like `bisect_left`), then collect forward while `.startswith(prefix)` holds.
@@hint
`most_borrowed`: tag each book with its position, `[(i, book) for i, book in enumerate(books)]`. In each round, the "largest" is the one with more loans, or equal loans and a smaller position.
@@solution
def stable_sort(records, key):
    items = records[:]
    for i in range(1, len(items)):
        current = items[i]
        k = key(current)
        j = i - 1
        while j >= 0 and key(items[j]) > k:
            items[j + 1] = items[j]
            j -= 1
        items[j + 1] = current
    return items

def catalogue(books):
    by_year = stable_sort(books, lambda b: b[2])
    return stable_sort(by_year, lambda b: b[1])

def title_index(books):
    return stable_sort(books, lambda b: b[0].lower())

def find_title(index, title):
    target = title.lower()
    lo, hi = 0, len(index) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        here = index[mid][0].lower()
        if here == target:
            return index[mid]
        if here < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return None

def starting_with(index, prefix):
    p = prefix.lower()
    lo, hi = 0, len(index)
    while lo < hi:
        mid = (lo + hi) // 2
        if index[mid][0].lower() < p:
            lo = mid + 1
        else:
            hi = mid
    found = []
    while lo < len(index) and index[lo][0].lower().startswith(p):
        found.append(index[lo])
        lo += 1
    return found

def most_borrowed(books, k):
    tagged = list(enumerate(books))
    if k > len(tagged):
        k = len(tagged)
    for i in range(k):
        best = i
        for j in range(i + 1, len(tagged)):
            pj, bj = tagged[j]
            pb, bb = tagged[best]
            if bj[3] > bb[3] or (bj[3] == bb[3] and pj < pb):
                best = j
        tagged[i], tagged[best] = tagged[best], tagged[i]
    return [book for pos, book in tagged[:k]]
:::

:::think title="Choosing the right tool each time"
Look at which algorithm each function used. A one-off sort of a small list: insertion sort is fine. Many title lookups: sort once, then O(log n) binary search each time. All titles with a prefix: binary search to the start, then a short walk. Just the top few: k rounds of selection instead of a whole sort. In real code you'd use `sorted`, `bisect` and `heapq.nlargest`, but the reasons for choosing each are exactly the ones you've just used.
:::

## Forge bonus: searching a rotated list

A sorted list has been **rotated**: some number of items were moved from the front to the end, so `[1, 3, 5, 7, 9, 11]` might now be `[7, 9, 11, 1, 3, 5]`. It's no longer sorted, so ordinary binary search fails, and a linear search is O(n). But it's made of **two sorted pieces**, and that's enough for an O(log n) search.

The key fact: if you cut the part you're searching in the middle, **at least one half is properly sorted**. You can tell which by comparing its ends, and for a sorted half you can tell at once whether the target lies inside it.

:::exercise id=forge2 points=30 title="Forge bonus: searching a rotated list"
The list holds different numbers. Write:

- `find_rotation(items)`: the position of the smallest item (the number of places it was rotated), in O(log n). Compare the middle with the **last** item: if `items[mid] > items[hi]`, the smallest is to the right of `mid`; otherwise it's at `mid` or to its left.
- `rotated_search(items, target)`: the position of `target` or -1, in O(log n), with a single binary search: at each step decide which half is sorted (`items[lo] <= items[mid]` means the left half is), check whether the target is inside the sorted half's range, and keep that half or the other.

Both must handle a list that wasn't rotated at all, a single item and an empty list (`find_rotation([])` is 0).
@@starter

@@tests
import random
def test_rotation():
    "find_rotation"
    assert find_rotation([7, 9, 11, 1, 3, 5]) == 3
    assert find_rotation([1, 3, 5]) == 0 and find_rotation([5, 1, 3]) == 1 and find_rotation([3, 5, 1]) == 2
    assert find_rotation([4]) == 0 and find_rotation([]) == 0
def test_search():
    "rotated_search"
    xs = [7, 9, 11, 1, 3, 5]
    for i, x in enumerate(xs):
        assert rotated_search(xs, x) == i
    assert rotated_search(xs, 4) == -1 and rotated_search([], 1) == -1 and rotated_search([2], 2) == 0
    rng = random.Random(8)
    for _ in range(200):
        base = sorted(rng.sample(range(100), rng.randint(1, 20)))
        r = rng.randint(0, len(base) - 1)
        rot = base[r:] + base[:r]
        assert find_rotation(rot) == (len(rot) - r) % len(rot)
        for t in (rot[rng.randint(0, len(rot) - 1)], -1, 100, 50):
            assert rotated_search(rot, t) == (rot.index(t) if t in rot else -1)

    "big and fast"
    n = 1_000_000
    rot = list(range(400_000, n)) + list(range(400_000))

@@hint
`find_rotation`: `lo, hi = 0, len(items) - 1`; while `lo < hi`, set `mid`; if `items[mid] > items[hi]` then `lo = mid + 1`, else `hi = mid`. The answer is `lo`.
@@hint
`rotated_search`: if `items[lo] <= items[mid]` (left half sorted): if `items[lo] <= target < items[mid]`, search left (`hi = mid - 1`), else right. Otherwise the right half is sorted: if `items[mid] < target <= items[hi]`, search right, else left.
@@solution
def find_rotation(items):
    if not items:
        return 0
    lo, hi = 0, len(items) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if items[mid] > items[hi]:
            lo = mid + 1
        else:
            hi = mid
    return lo

def rotated_search(items, target):
    lo, hi = 0, len(items) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if items[mid] == target:
            return mid
        if items[lo] <= items[mid]:
            if items[lo] <= target < items[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:
            if items[mid] < target <= items[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1
