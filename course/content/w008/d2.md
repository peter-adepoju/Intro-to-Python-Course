## Warm-up

:::predict
word = "jello"
print("h" + word[1:])
print(word)
:::

To "change" a string you had to build a new one; the old one was untouched. Lists are different.

## Changing an item

Assign to an index, and that item of the list is replaced:

:::example
fruits = ["apple", "banana", "cherry"]
fruits[1] = "blueberry"
print(fruits)
fruits[-1] = fruits[-1].upper()
print(fruits)
:::

Try the same with a string and Python refuses, as you saw in Week 5. A list is **mutable**: it can be changed after it's made. A string is **immutable**. Press X-ray on the example: there's only ever **one** list object; one of its slots is pointed at a new value.

:::key
`items[i] = value` changes the list in place. Lists are mutable; strings and numbers are not.
:::

### Swapping two items

The swap trick from Week 1 works on items too:

:::example
order = ["c", "b", "a"]
order[0], order[2] = order[2], order[0]
print(order)
:::

### Changing a slice

You can replace a whole slice with the items of another list, even a different number of them:

:::example
numbers = [1, 2, 3, 4, 5]
numbers[1:3] = [20, 30]
print(numbers)
numbers[1:3] = [9]
print(numbers)
numbers[1:1] = [7, 7, 7]
print(numbers)
:::

The last one replaces the empty slice at position 1, which **inserts** three items without removing any.

## Deleting

`del` removes an item, or a slice, and closes the gap:

:::example
letters = ["a", "b", "c", "d", "e", "f"]
del letters[0]
print(letters)
del letters[-2:]
print(letters)
del letters[::2]
print(letters)
:::

Try the changing operations in the list lab. Each run keeps its result, so you can chain them:

## Mutation versus rebinding

This is the most important idea of the day. There are two very different ways to "change" `x`:

- **Mutation**: change the list object itself. `x[0] = 5`, `x.append(5)`, `del x[0]`.
- **Rebinding**: make a **new** object and move the name `x` to it. `x = x + [5]`, `x = []`.

When only one name points at the list, you can't see the difference. When two do, you can:

:::example title="Mutation: both names see it"
a = [1, 2, 3]
b = a
a.append(4)
print("a:", a)
print("b:", b)
:::

:::example title="Rebinding: only one name moves"
a = [1, 2, 3]
b = a
a = a + [4]
print("a:", a)
print("b:", b)
:::

X-ray both. In the first, there's one list with two names on it, and appending changes that one list. In the second, `a + [4]` builds a **new** list, and only `a` is moved to it; `b` still points at the old one.

This is the labels picture from Week 1, Day 3 doing real work. With numbers and strings it never mattered, because they can't be changed. With lists it matters all the time. You'll spend Day 5 on it.

:::warn title="+= is mutation for lists"
For numbers, `n += 1` means `n = n + 1`. For lists, `x += [4]` **changes the list in place**, like `append`, rather than making a new list. So with two names on one list, `a += [4]` changes what `b` sees, but `a = a + [4]` doesn't.
:::

:::example
a = [1, 2, 3]
b = a
a += [4]
print(b)
:::

## Changing every item

To change every item, loop over the **indexes** and assign through them:

:::example
prices = [100, 250, 80]
for i in range(len(prices)):
    prices[i] = prices[i] * 1.1
print(prices)
:::

A tempting mistake is to change the loop variable instead:

:::example title="This changes nothing"
prices = [100, 250, 80]
for p in prices:
    p = p * 1.1
print(prices)
:::

The loop variable `p` is a **name** pointing at each item in turn. `p = p * 1.1` moves the name `p` to a new number; the list's slots still point at the old ones. Only assigning **through the list**, `prices[i] = ...`, changes a slot.

:::mistake
`for item in items: item = ...` never changes the list. Use `for i in range(len(items)): items[i] = ...`, or build a new list.
:::

### Don't change a list's length while looping over it

Removing items from a list while a `for` loop walks over it makes the loop skip items, because everything after the removed one shifts left:

:::example title="A skipped item"
nums = [1, 2, 2, 3]
for n in nums:
    if n == 2:
        nums.remove(n)
print(nums)
:::

(`.remove(v)` deletes the first item equal to `v`; you'll meet it properly tomorrow.) One `2` survived. The safe way is to build a new list of the items you want to **keep** (the filter pattern), which you'll practise in Day 4.

## Functions that change lists

Because a parameter is just another name for the caller's object, a function can **change** a list it's given, and the caller will see the change:

:::example
def add_tax(prices):
    for i in range(len(prices)):
        prices[i] = round(prices[i] * 1.075, 2)

basket = [100, 200]
add_tax(basket)
print(basket)
:::

That's very different from numbers and strings, where a function could never affect the caller's variable. So for every function that takes a list, decide which kind it is, and say so in its docstring:

- **It changes the list in place** and returns `None`, like `list.sort()` and `append`.
- **It leaves the list alone and returns a new one**, like `sorted()`.

:::example title="Two designs, both clear"
def scale(values, factor):
    """Multiply every item of values by factor, in place. Returns None."""
    for i in range(len(values)):
        values[i] *= factor

def scaled(values, factor):
    """Return a new list: every item of values times factor."""
    result = []
    for v in values:
        result.append(v * factor)
    return result

data = [1, 2, 3]
print(scaled(data, 10), data)
scale(data, 10)
print(data)
:::

:::tip
Prefer functions that return a new list. They can't surprise anyone by changing data behind their back. Change in place when the list is large and copying would waste memory, or when changing it is the whole point, and say so in the docstring.
:::

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: rotate by any amount"
Write `reverse_section(items, start, end)` that reverses the items from position `start` up to but not including `end`, **in place**, by swapping pairs from the outside in (don't use slicing with `[::-1]` or `.reverse()`).

Then write `rotate(items, k)` that moves every item `k` places to the **right**, wrapping round, in place, using three calls to `reverse_section`: reverse the whole list, then the first `k` items, then the rest. `rotate([1, 2, 3, 4, 5], 2)` gives `[4, 5, 1, 2, 3]`. `k` may be bigger than the length (use `%`), and an empty list stays empty.
@@starter

@@tests
def test_reverse_section():
    "reverse_section"
    a = [1, 2, 3, 4, 5, 6]
    reverse_section(a, 1, 5)
    assert a == [1, 5, 4, 3, 2, 6]
    b = [1, 2]
    reverse_section(b, 0, 2)
    assert b == [2, 1]
    c = [1, 2, 3]
    reverse_section(c, 1, 1)
    assert c == [1, 2, 3]
    assert "[::-1]" not in source and ".reverse()" not in source, "Swap pairs yourself."
def test_rotate():
    "rotate"
    for items, k, want in [([1, 2, 3, 4, 5], 2, [4, 5, 1, 2, 3]), ([1, 2, 3], 0, [1, 2, 3]), ([1, 2, 3], 4, [3, 1, 2]), ([], 3, []), (["a"], 9, ["a"])]:
        x = list(items)
        assert rotate(x, k) is None, "rotate works in place and returns None."
        assert x == want, f"rotate({items}, {k}) should give {want}, got {x}."
@@hint
In `reverse_section`, keep two positions, `i = start` and `j = end - 1`. While `i < j`, swap `items[i]` and `items[j]`, then move them towards each other.
@@hint
In `rotate`, first set `k = k % len(items)` (but only if the list isn't empty). Then reverse `0` to `n`, `0` to `k`, and `k` to `n`.
@@solution
def reverse_section(items, start, end):
    i, j = start, end - 1
    while i < j:
        items[i], items[j] = items[j], items[i]
        i += 1
        j -= 1

def rotate(items, k):
    n = len(items)
    if n == 0:
        return
    k = k % n
    reverse_section(items, 0, n)
    reverse_section(items, 0, k)
    reverse_section(items, k, n)
:::
