## Warm-up

:::predict
def paths(steps):
    if steps == 0:
        return 1
    if steps < 0:
        return 0
    return paths(steps - 1) + paths(steps - 2)

print([paths(n) for n in range(7)])
:::

Those are the Fibonacci numbers again. `paths(n)` counts the ways to climb n stairs taking 1 or 2 at a time: your first step is either 1 stair or 2, and after that you have a smaller staircase. Two choices, two recursive calls.

## Choices make trees

**Tree recursion** is recursion where a call makes **more than one** recursive call. Each call branches, so the calls form a tree. It fits any problem where you face a **choice**:

1. Pick one decision to make now (the first stair: 1 or 2? the first coin: use it or not?).
2. For **each** option, recurse on the smaller problem that's left.
3. Combine the results: add them up to count the ways, collect them to list the ways, or take the best to optimise.

Here's the climbing problem as a tree. Each call tries both first steps:

:::widget calltree caption="Each call branches into two: take 1 stair, or take 2. Calls that land exactly on 0 count as one way; calls that overshoot count as none. Notice how often the same call repeats."
{"code": "def paths(steps):\n    if steps == 0:\n        return 1\n    if steps < 0:\n        return 0\n    return paths(steps - 1) + paths(steps - 2)", "call": "paths(4)", "calls": ["paths(3)", "paths(4)", "paths(6)"]}
:::

:::key
In tree recursion, each call tries every choice for one decision, recursing once per choice, and combines what comes back. The base cases say what happens when there's nothing left to decide, or when a choice has gone wrong.
:::

## Counting the ways

To **count** the ways, add up the counts for each choice.

### Making change

How many ways can you make 10 naira from coins of 1, 2 and 5 (in any amounts, where order doesn't matter)? The trick is to choose **about one coin type at a time**: either you use at least one of the first type, or you never use it.

:::example
def ways(amount, coins):
    if amount == 0:
        return 1
    if amount < 0 or not coins:
        return 0
    use_first = ways(amount - coins[0], coins)
    skip_first = ways(amount, coins[1:])
    return use_first + skip_first

print(ways(10, [1, 2, 5]))
print(ways(100, [1, 2, 5, 10, 20, 50]))
:::

Read it with the leap of faith: every way of making the amount either uses at least one `coins[0]` (so take one off and make the rest, still allowed to use it again) or uses none (so make the whole amount with the other coins). Those two groups don't overlap, and together they're everything, so adding them counts each way exactly once.

:::mistake
Choosing "which coin next?" from all of them at every step counts `1 + 2` and `2 + 1` as different ways. If order doesn't matter, decide about one item at a time: use it, or move past it for good.
:::

### Paths in a grid

How many routes are there from the top-left corner of a grid to the bottom-right, moving only right or down? From any square, the routes are the routes after going right plus the routes after going down:

:::example
def routes(rows, cols):
    if rows == 1 or cols == 1:
        return 1
    return routes(rows - 1, cols) + routes(rows, cols - 1)

print(routes(2, 2), routes(3, 3), routes(4, 6))
:::

## Listing the ways

To **list** the ways instead of counting them, build each answer from the choice made now, plus each of the answers to the smaller problem:

:::example
def climbs(steps):
    """Every way to climb `steps` stairs, 1 or 2 at a time, as lists of step sizes."""
    if steps == 0:
        return [[]]
    if steps < 0:
        return []
    return [[1] + rest for rest in climbs(steps - 1)] + [[2] + rest for rest in climbs(steps - 2)]

for c in climbs(4):
    print(c)
:::

Two base cases with very different answers:

- `[[]]` for 0 stairs: there is **one** way to climb no stairs, which is to do nothing. That one way is the empty list.
- `[]` for a negative number: there are **no** ways.

Getting these right is the whole trick. With `[]` for 0, every list would be empty, because there would be nothing to put a first step in front of.

### Binary strings

All the strings of n binary digits: each is either `"0"` or `"1"`, followed by every string of n - 1 digits.

:::example
def binary_strings(n):
    if n == 0:
        return [""]
    shorter = binary_strings(n - 1)
    return ["0" + s for s in shorter] + ["1" + s for s in shorter]

print(binary_strings(3))
:::

Notice `shorter` is worked out **once** and used twice. Calling `binary_strings(n - 1)` twice would double the work at every level.

## How big is the tree?

The number of calls is the size of the tree. If each call makes **two** calls and the depth goes down by **one** each time, the tree has about 2 to the power n calls:

| n | 2 to the n |
|---|---|
| 10 | about a thousand |
| 20 | about a million |
| 30 | about a billion |
| 40 | about a trillion |

Each extra level doubles the work. That's why `paths(40)` takes noticeably long, and `paths(100)` would never finish. Sometimes the size really is that big: there are 2 to the n binary strings of length n, so listing them all can't be faster. But often the tree repeats the same calls over and over, and tomorrow you'll learn to make those repeats free.

:::example
calls = 0
def paths(steps):
    global calls
    calls += 1
    if steps <= 0:
        return 1 if steps == 0 else 0
    return paths(steps - 1) + paths(steps - 2)

for n in (10, 15, 20, 25):
    calls = 0
    paths(n)
    print(n, calls)
:::

## Stopping early

Sometimes you only want to know **whether** there's a way, not how many. Then stop as soon as one branch succeeds, with `or` (which short-circuits) or an early `return`:

:::example
def can_make(amount, coins):
    """Can `amount` be made exactly from the coins, each used at most once?"""
    if amount == 0:
        return True
    if amount < 0 or not coins:
        return False
    return can_make(amount - coins[0], coins[1:]) or can_make(amount, coins[1:])

print(can_make(12, [5, 3, 9, 2]), can_make(1, [5, 3, 9, 2]))
:::

You can also **prune**: skip branches that can't possibly work. If the coins are sorted from smallest to largest and the smallest is already bigger than the amount, nothing in that branch can succeed, so return straight away. Pruning doesn't change the answer, only how much of the tree you visit.

Use the first coin: put `coins[0]` in front of every way to make `amount - coins[0]` with the same coins. Skip it: every way to make `amount` with `coins[1:]`. Put the "use it" lists first.
@@solution
def change_ways(amount, coins):
    if amount == 0:
        return [[]]
    if amount < 0 or not coins:
        return []
    use = [[coins[0]] + rest for rest in change_ways(amount - coins[0], coins)]
    skip = change_ways(amount, coins[1:])
    return use + skip
:::

:::exercise id=target_sum points=15 title="Hit the target"
Write `subset_sum(numbers, target)` that returns `True` if some of the numbers (each used at most once) add up exactly to `target`. Stop as soon as you find one. Then write `count_subsets(numbers, target)` that counts how many different selections (by position) add up to it.
@@starter

@@tests

    "several"

def subset_sum(numbers, target):
    if target == 0:
        return True
    if not numbers:
        return False
    return subset_sum(numbers[1:], target - numbers[0]) or subset_sum(numbers[1:], target)

def count_subsets(numbers, target):
    if not numbers:
        return 1 if target == 0 else 0
    return count_subsets(numbers[1:], target - numbers[0]) + count_subsets(numbers[1:], target)

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: the best basket"
You have a basket that can hold at most `capacity` kilograms, and some items, each a tuple `(name, weight, value)`. Which items should you take to get the most value without going over the weight? (This is the famous **knapsack problem**.) Write `best_basket(items, capacity)` that returns a tuple `(value, names)`: the best total value, and the sorted list of the names taken. Decide about one item at a time: take it (if it fits) or leave it, and keep whichever choice gives more value. If several selections give the same best value, any of them is accepted.
@@starter

@@tests
from itertools import combinations
def brute(items, cap):
    best = 0
    for r in range(len(items) + 1):
        for c in combinations(items, r):
            if sum(i[1] for i in c) <= cap:
                best = max(best, sum(i[2] for i in c))
    return best
ITEMS = [("rice", 5, 60), ("beans", 3, 50), ("yam", 4, 70), ("oil", 2, 30), ("pepper", 1, 15)]
def test_values():
    "several"
    v, names = best_basket(ITEMS, 8)
    assert v == brute(ITEMS, 8) == 135
    chosen = [i for i in ITEMS if i[0] in names]
    assert sum(i[1] for i in chosen) <= 8 and sum(i[2] for i in chosen) == v and names == sorted(names)
    assert best_basket(ITEMS, 0) == (0, [])
    assert best_basket([], 10) == (0, [])
    for cap in range(16):
        assert best_basket(ITEMS, cap)[0] == brute(ITEMS, cap), cap
@@hint
Base case: no items, or no capacity, gives `(0, [])`. Otherwise work out "leave the first item": `best_basket(items[1:], capacity)`. If the first item fits, also "take it": the result for the rest with `capacity - weight`, plus its value and name. Return the better of the two.
@@solution
def best_basket(items, capacity):
    if not items or capacity <= 0:
        return 0, []
    name, weight, value = items[0]
    best = best_basket(items[1:], capacity)
    if weight <= capacity:
        v, names = best_basket(items[1:], capacity - weight)
        if v + value > best[0]:
            best = (v + value, sorted(names + [name]))
    return best
:::
