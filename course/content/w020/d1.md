## Warm-up

:::predict
import math
import math as m
from math import sqrt

print(math.sqrt(16), m.sqrt(25), sqrt(36))
print(math is m)
:::

Three different ways of writing an import, all reaching the same `sqrt`. And `math is m` is `True`: there's only one `math` module object, which both names refer to. By the end of today you'll know why.

## A module is a file

A **module** is just a Python file. The file `helpers.py` is the module `helpers`. Everything defined at the top level of the file (functions, variables, classes) becomes a name inside the module, which you reach with a dot.

This page has a file called `greetings.py`. Open it to see what's inside:

:::files
=== greetings.py
"""Friendly messages, in a few languages."""

DEFAULT = "en"
HELLO = {"en": "Hello", "yo": "Ẹ n lẹ", "fr": "Bonjour", "ha": "Sannu"}

def greet(name, lang=DEFAULT):
    return f"{HELLO.get(lang, HELLO[DEFAULT])}, {name}!"

def farewell(name):
    return f"Goodbye, {name}."
:::

Any program on this page can import it:

:::example
import greetings

print(greetings.greet("Ada"))
print(greetings.greet("Tunde", "yo"))
print(greetings.HELLO["ha"])
print(greetings.DEFAULT)
:::

`greetings.greet` reads as "the `greet` that lives in `greetings`". The dot keeps names from different modules apart: `greetings.greet` and a `greet` of your own can't clash.

Modules come from three places:

| Kind | Examples | Where from |
|---|---|---|
| Built into the language | `sys`, `math`, `builtins` | part of Python itself |
| The **standard library** | `random`, `datetime`, `json`, `collections`, `pathlib` | installed with every copy of Python |
| **Third-party** packages | `requests`, `numpy`, `pandas` | installed separately with `pip` (Week 22) |
| Your own | `greetings`, `helpers` | files you write |

A **package** is a folder of modules, imported with dots: `os.path`, `email.mime.text`. You'll make one tomorrow.

## Four ways to import

**`import module`**: the whole module, under its own name. The safest and clearest: every use says where the name came from.

```
import random
random.choice(["a", "b"])
```

**`import module as alias`**: the same, under a shorter or clearer name. Some aliases are conventions everyone uses: `import numpy as np`, `import pandas as pd`.

**`from module import name1, name2`**: copy particular names into your program, so you can use them without the dot. Good for a few names you use often:

```
from math import sqrt, pi
from collections import Counter
```

**`from module import *`**: copy **every** public name in. Avoid it in programs: you can't tell where a name came from, and it can silently replace your own names.

:::example
def floor(x):
    return "my own floor function"

from math import *             # quietly replaces floor with math.floor

print(floor(2.7))
:::

You've seen a `from` import go wrong here too: `from math import sqrt` copies the name `sqrt`, but if you later do `sqrt = 5`, only your copy changes; `math.sqrt` is untouched.

:::key
`import x` and use `x.name` by default. Use `from x import name` for a few names you use a lot. Avoid `from x import *`. Put imports at the top of the file, standard library first, then third-party, then your own modules.
:::

## What happens on import

When Python meets `import greetings` for the first time, it:

1. **Finds** the file: it looks through the folders listed in `sys.path`, in order. The first is the folder of the program being run, so your own files are found first.
2. **Runs** the file, top to bottom, in a fresh namespace. Every `def` creates a function, every assignment creates a variable, and any `print` actually prints.
3. **Remembers** the result as a module object in `sys.modules`, a dictionary from module names to modules.
4. **Binds** a name in your program to the module object.

The second time anything imports the same module, step 1 to 3 are skipped: Python finds it in `sys.modules` and hands back the same object. A module's top-level code runs **once** per program, however many times it's imported. That's why `math is m` was `True` in the warm-up.

:::files
=== noisy.py
print("noisy.py is running!")
COUNT = 0

def bump():
    global COUNT
    COUNT += 1
    return COUNT
:::

:::example
import sys

import noisy
import noisy            # nothing printed: already imported
import noisy as n

print(noisy.bump(), n.bump(), noisy.COUNT)
print("noisy" in sys.modules, sys.modules["noisy"] is noisy)
:::

`noisy` and `n` are two names for the **same** module, so they share `COUNT`.

To see where Python looks:

:::example
import sys

for folder in sys.path[:4]:
    print(folder)
:::

(In the browser the folders look unusual; on your own computer you'll see your project folder, then the standard library's folder, then `site-packages`, where `pip` puts third-party packages.)

## Exploring a module

A module is an object like any other. `dir` lists its names, `help` shows its documentation (from docstrings), and a few attributes say where it came from:

:::example
import greetings

print(greetings.__name__)
print(greetings.__doc__)
print([name for name in dir(greetings) if not name.startswith("_")])
print(greetings.__file__.split("/")[-1])
:::

Names starting with `_` are private by convention: the module's own business. `from module import *` leaves them out.

For the standard library, `help(module)` works in any Python session, and the official documentation at docs.python.org describes every module, with examples. Learning to read it is part of this week's work.

:::example
import statistics

print(statistics.__doc__.splitlines()[0])
print([n for n in dir(statistics) if not n.startswith("_")][:12])
:::

## Classic mistakes

**Naming your file after a module.** If you save your own experiment as `random.py` and then `import random` in it, Python finds **your** file first (its folder is first in `sys.path`), and `random.randint` doesn't exist. The error is confusing: `AttributeError: module 'random' has no attribute 'randint'`. Never name your files `random.py`, `math.py`, `statistics.py`, `string.py`, `csv.py` and so on.

**Importing a name that isn't there:** `from math import squareroot` raises `ImportError: cannot import name 'squareroot' from 'math'`, which at least tells you exactly what's wrong.

**Expecting an edit to take effect without rerunning:** because modules are imported once, a running program keeps the old version of a module you've edited. Run the program again (or, in an interactive session, restart it).

**Circular imports:** if `a.py` imports `b` and `b.py` imports `a`, one of them runs while the other is only half finished, and names may be missing. The fix is to reorganise: move what both need into a third module.

:::mistake
`import greetings.py` is wrong: a module's name doesn't include `.py`. Write `import greetings`.
:::

:::exercise id=explore points=15 title="Explore a module"
Write `public_names(module)` that returns a sorted list of the names in a module that don't start with `_`, and `functions_in(module)` that returns a sorted list of just those public names whose value is a function you can call (`callable(...)`) but isn't a class (`not isinstance(value, type)`). Use `dir` and `getattr`.
@@files
=== shapes.py
"""Areas of simple shapes."""

PI_ISH = 3.14
_cache = {}

def circle(r):
    return math.pi * r * r

def square(s):
    return s * s

    return None
@@starter
import shapes

@@tests
def test_values():
    "several"
    import shapes
    assert public_names(shapes) == ["PI_ISH", "circle", "math", "square"]
    assert functions_in(shapes) == ["circle", "square"]
    import statistics
    assert "mean" in functions_in(statistics) and "StatisticsError" not in functions_in(statistics)
@@solution
import shapes

def public_names(module):
    return sorted(n for n in dir(module) if not n.startswith("_"))

def functions_in(module):
    result = []
    for n in public_names(module):
        value = getattr(module, n)
        if callable(value) and not isinstance(value, type):
            result.append(n)
    return result

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: who imports whom"
A project has several `.py` files (given as a dictionary from file name to its source code). Write:

- `imports_of(source)`: the sorted list of **module names** a piece of source code imports, from lines like `import a`, `import a, b`, `import a as x`, `from a import b` and `from a.b import c` (give the top-level name, `a`). Use the `ast` module: `ast.parse(source)` gives a tree; walk it with `ast.walk` and look for `ast.Import` nodes (each has `.names`, whose items have `.name`) and `ast.ImportFrom` nodes (with `.module`).
- `local_graph(files)`: a dictionary from each module name (file name without `.py`) to the sorted list of **other files in the project** it imports.
- `has_cycle(graph)`: `True` if some module imports itself through a chain (a imports b, b imports a), using the flood-fill style search from Week 16 from every module.
@@starter
import ast

@@tests
FILES = {
    "main.py": "import os\nfrom shop import basket\nimport prices as p, reports\n",
    "shop.py": "from prices import vat\nimport json\n",
    "prices.py": "import math\nVAT = 0.2\n",
    "reports.py": "import shop\nfrom collections import Counter\n",
}
def test_imports():
    "imports_of"
    assert imports_of(FILES["main.py"]) == ["os", "prices", "reports", "shop"]
    assert imports_of("from a.b.c import d\nimport x.y\n") == ["a", "x"]
    assert imports_of("print('no imports')") == []
def test_graph():
    "local_graph"
    assert local_graph(FILES) == {"main": ["prices", "reports", "shop"], "shop": ["prices"], "prices": [], "reports": ["shop"]}
def test_cycle():
    "has_cycle"
    assert has_cycle(local_graph(FILES)) is False
    loop = dict(FILES)
    loop["prices.py"] = "import reports\n"
    assert has_cycle(local_graph(loop)) is True
    assert has_cycle({"a": ["a"]}) is True and has_cycle({}) is False
@@hint
For `has_cycle`: for each module `start`, search from its imports, keeping a `seen` set; if the search ever reaches `start` again, there's a cycle.
@@solution
import ast

def imports_of(source):
    found = set()
    for node in ast.walk(ast.parse(source)):
        if isinstance(node, ast.Import):
            for alias in node.names:
                found.add(alias.name.split(".")[0])
        elif isinstance(node, ast.ImportFrom) and node.module:
            found.add(node.module.split(".")[0])
    return sorted(found)

def local_graph(files):
    names = {f[:-3] for f in files if f.endswith(".py")}
    return {f[:-3]: [m for m in imports_of(src) if m in names] for f, src in files.items() if f.endswith(".py")}

def has_cycle(graph):
    for start in graph:
        seen = set()
        stack = list(graph[start])
        while stack:
            m = stack.pop()
            if m == start:
                return True
            if m in seen:
                continue
            seen.add(m)
            stack.extend(graph.get(m, []))
    return False
:::
