## Writing a file

Open a file with mode `"w"` (for **write**) as the second argument, and call `write` with a string:

:::example
with open("greeting.txt", "w") as f:
    f.write("Hello, file!\n")
    f.write("A second line.\n")
with open("greeting.txt") as f:
    print(f.read())
:::

Run it, and the panel under the output shows the files afterwards, with `greeting.txt` marked new. Two things to notice:

- `write` writes **exactly** the string you give it. It doesn't add a newline: you must put `"\n"` at the end of each line yourself.
- `write` only takes strings. Write a number with `str(n)` or an f-string.

:::example
scores = {"Ada": 93, "Bo": 41}
with open("out.txt", "w") as f:
    for name, mark in scores.items():
        f.write(f"{name},{mark}\n")
with open("out.txt") as f:
    print(f.read(), end="")
:::

### print to a file

`print` has a `file` argument. With it, `print` writes to the file instead of the screen, adding spaces and the newline just as it always does:

:::example
with open("report.txt", "w") as f:
    print("Report", file=f)
    print("Ada", 93, file=f)
    print("Bo", 41, sep=": ", file=f)
with open("report.txt") as f:
    print(f.read(), end="")
:::

Use whichever is clearer. `print(..., file=f)` is handy when you already have a program that prints a report and you want it in a file instead.

:::warn
Until a file is closed, some of what you wrote may still be waiting in memory rather than on the disk. Another reason to always use `with`: the data is safely written when the block ends.
:::

## Modes

The mode decides what happens to a file that already exists:

| Mode | Meaning | If the file exists | If it doesn't |
|---|---|---|---|
| `"r"` | read (the default) | reads it | `FileNotFoundError` |
| `"w"` | write | **empties it first** | creates it |
| `"a"` | append | adds to the end | creates it |
| `"x"` | create | `FileExistsError` | creates it |

`"w"` is the dangerous one: the moment you open a file with it, the old contents are gone, before you've written anything.

:::example
with open("todo.txt", "w") as f:
    f.write("water plants\n")
with open("todo.txt") as f:
    print(f.read(), end="")
:::

The two old tasks were destroyed. To **add** to a file, use `"a"`:

:::example
with open("todo.txt", "a") as f:
    f.write("water plants\n")
with open("todo.txt") as f:
    print(f.read(), end="")
:::

Append is the mode for **logs**: each run adds its lines, and nothing is lost.

`"x"` refuses to touch an existing file, which protects you from overwriting something by accident:

:::example error=yes
with open("scores.txt", "x") as f:
    f.write("new\n")
:::

:::mistake
Opening the file you're reading with `"w"`, to "update" it, empties it before you've read it. Read everything first, close it, and then write.
:::

## Saving and loading data

With reading and writing, your data can outlive your program. The simplest approach: one record per line, fields separated by commas. Save by joining; load by splitting:

:::example
def save(scores, name):
    with open(name, "w") as f:
        for person, mark in scores.items():
            f.write(f"{person},{mark}\n")

def load(name):
    scores = {}
    with open(name) as f:
        for line in f:
            person, mark = line.strip().split(",")
            scores[person] = int(mark)
    return scores

save({"Cy": 78, "Di": 55}, "saved.txt")
print(load("saved.txt"))
:::

For nested data, JSON (from Week 10) does the work: `json.dump(data, f)` writes data to an open file and `json.load(f)` reads it back. These are `dumps` and `loads` without the **s**, which stands for **string**.

:::example
import json
settings = {"theme": "dark", "recent": ["a.txt", "b.txt"]}
with open("settings.json", "w") as f:
    json.dump(settings, f, indent=2)
with open("settings.json") as f:
    loaded = json.load(f)
print(loaded["recent"][0])
:::

## Paths with pathlib

A **path** says where a file is: `marks.txt`, `data/2026/marks.txt`, or `/home/ada/data/marks.txt`. Paths are written differently on different systems (Windows uses `\` between folders, macOS and Linux use `/`), so building them by gluing strings together causes bugs. The `pathlib` module gives you `Path` objects instead:

:::example
from pathlib import Path
p = Path("data") / "2026" / "marks.csv"
print(p)
print(p.name)
print(p.stem)
print(p.suffix)
print(p.parent)
print(p.with_suffix(".txt"))
:::

The `/` operator joins parts of a path, and uses the right separator for the computer it runs on. The parts:

- `name`: the last part, `marks.csv`;
- `stem`: the name without its suffix, `marks`;
- `suffix`: the extension, `.csv`;
- `parent`: the folder it's in, `data/2026`.

A `Path` can be passed to `open` anywhere a string can. And it has shortcuts for small files:

:::example
from pathlib import Path
p = Path("note.txt")
p.write_text("short note\n")
print(p.read_text())
print(p.exists(), Path("nothing.txt").exists())
:::

`read_text` and `write_text` open, read or write, and close in one step. They're perfect for small files; for big files, loop over the lines with `open` as before.

### Absolute and relative paths

`Path("marks.txt")` is **relative**: it's found from the current folder. `Path.cwd()` is the current folder, and `p.resolve()` gives the **absolute** path, from the top of the disk:

:::example
from pathlib import Path
print(Path.cwd())
print(Path("marks.txt").resolve())
:::

(The folder here is the temporary one this website's Python runs in. On your own computer it would be wherever you ran the program.)

## Folders

`mkdir` makes a folder. `parents=True` makes any missing folders above it, and `exist_ok=True` means "fine if it's already there":

:::example
from pathlib import Path
out = Path("results") / "2026"
out.mkdir(parents=True, exist_ok=True)
(out / "summary.txt").write_text("done\n")
print(sorted(p.name for p in Path(".").iterdir()))
print(list(Path(".").glob("*.txt")))
:::

`iterdir()` gives everything in a folder; `glob("*.txt")` gives the paths whose names match a pattern, where `*` means "any characters". `rglob` does the same through every folder inside, too.

:::tip
Programs that make several output files should put them in their own folder, and build every path from one `Path` at the top. Then changing where the output goes is a one-line change.
:::

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: a diary"
Write a small diary program with three functions, storing each day's entries in its own file inside a `diary` folder, named like `diary/2026-10-27.txt`:

- `add(date, text)` appends `text` as a new line to that day's file, making the folder if needed.
- `read_day(date)` returns that day's entries as a list of strings, or `[]` if there's no file for that day.
- `summary()` returns one line per day that has a file, in date order, like `2026-10-27: 2 entries` (or `1 entry` for one), joined with `"\n"`. It returns `"Empty diary"` if there's no `diary` folder or no files in it.
@@starter
from pathlib import Path
DIARY = Path("diary")

@@tests
def test_add_read():
    "add and read_day"
    reset_files()
    assert read_day("2026-10-27") == []
    add("2026-10-27", "Started Week 11.")
    add("2026-10-27", "Read my first file.")
    assert read_day("2026-10-27") == ["Started Week 11.", "Read my first file."]
    assert read_file("diary/2026-10-27.txt") == "Started Week 11.\nRead my first file.\n"
def test_summary():
    "summary"
    reset_files()
    assert summary() == "Empty diary"
    add("2026-10-28", "b")
    add("2026-10-27", "a1")
    add("2026-10-27", "a2")
    assert summary() == "2026-10-27: 2 entries\n2026-10-28: 1 entry"
@@hint
`DIARY / f"{date}.txt"` is the day's path. In `add`, call `DIARY.mkdir(exist_ok=True)` first, then open the file with `"a"`.
@@hint
In `summary`, `sorted(DIARY.glob("*.txt"))` gives the files in date order (dates written year-month-day sort correctly as text). `p.stem` is the date.
@@solution
from pathlib import Path
DIARY = Path("diary")

def day_path(date):
    return DIARY / f"{date}.txt"

def add(date, text):
    DIARY.mkdir(exist_ok=True)
    with open(day_path(date), "a") as f:
        f.write(text + "\n")

def read_day(date):
    path = day_path(date)
    if not path.exists():
        return []
    return path.read_text().splitlines()

def summary():
    if not DIARY.exists():
        return "Empty diary"
    lines = []
    for path in sorted(DIARY.glob("*.txt")):
        n = len(path.read_text().splitlines())
        lines.append(f"{path.stem}: {n} {'entry' if n == 1 else 'entries'}")
    return "\n".join(lines) if lines else "Empty diary"
:::
