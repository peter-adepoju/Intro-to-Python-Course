## Warm-up

:::predict
n = 0
while True:
    n += 4
    if n > 10:
        break
print(n)
:::

If you got that right, you traced it in your head: 4, 8, 12, stop. Today you'll make that a dependable method that works for loops far too long to hold in your head.

## Why trace by hand?

X-ray shows you what a program does. Tracing by hand shows you what **you think** it does. A bug is exactly the place where the two disagree, so the skill is to write down your expectation first, then compare. Professional programmers trace in their heads all the time; they learned by doing it on paper.

## The trace table, pass by pass

On Day 1 of this week you saw a trace table with one row for every **line** Python runs. For loops, a more compact table is usually better: one row each time the **condition is checked**, showing every variable at that moment.

```python
total = 0
n = 5
while n > 0:
    total += n
    n -= 2
print(total)
```

| check | `n` | `total` | `n > 0`? |
|---|---|---|---|
| 1 | 5 | 0 | True |
| 2 | 3 | 5 | True |
| 3 | 1 | 8 | True |
| 4 | -1 | 9 | False |

Read down the table and every question answers itself:

- The body ran **3** times (the number of `True` rows).
- The final values are in the last row: `n` is -1, `total` is 9.
- It prints `9`.

Now check it against the figure. This one shows a row for every line, so you can see how the compact table is the rows at the `while` line:

:::widget tracetable caption="Find the rows for line 3, the while line. Those rows are the compact trace table. You can edit the program and trace your own."
{"code": "total = 0\nn = 5\nwhile n > 0:\n    total += n\n    n -= 2\nprint(total)"}
:::

:::tip
When tracing on paper: draw the columns first, fill the **first row** from the lines before the loop, then work through the body once per row. Cross nothing out; just add the next row.
:::

Try one on paper before running it:

:::predict
a = 1
b = 1
count = 0
while b < 30:
    a, b = b, a + b
    count += 1
print(count, a, b)
:::

Those are the **Fibonacci numbers**: each one is the sum of the two before. The pair `a, b` slides along the sequence one step per pass.

## What stays true: loop invariants

Look back at the table for the first loop. Something is true in **every** row: `total` plus all the numbers still to come equals 5 + 3 + 1. A statement that is true every time the condition is checked is called a **loop invariant**.

For the sum loop from Day 2:

```python
total = 0
i = 1
while i <= n:
    total += i
    i += 1
```

the invariant is: **`total` is the sum of every number before `i`**, that is 1 + 2 + ... + (i − 1).

- It's true at the start: `i` is 1, nothing has been added, and `total` is 0.
- If it's true at one check, the body keeps it true: it adds `i` and then moves `i` on.
- When the loop ends, `i` is `n + 1`, so the invariant says `total` is 1 + 2 + ... + n. That's exactly the answer you wanted.

You don't need to write invariants down for every loop. But asking "what does this variable **mean** at each check?" is the fastest way to understand a loop someone else wrote, and the best way to get your own loop right first time. You'll use invariants seriously in Phase 4, when you prove that algorithms work.

:::key
For every accumulator, be able to finish this sentence: "Each time the condition is checked, this variable holds ..."
:::

## Making a loop report on itself

When a loop misbehaves and you can't see why, make it **print its own trace table**. Add a print at the top of the body that shows every variable:

:::example title="A debugging print"
total = 0
n = 5
while n > 0:
    print("n:", n, "total:", total)
    total += n
    n -= 2
print("result:", total)
:::

Python has a shortcut made for this. In an f-string, `{n=}` prints the name, an equals sign and the value:

:::example title="The = shortcut"
total = 0
n = 5
while n > 0:
    print(f"{n=} {total=}")
    total += n
    n -= 2
print(f"{total=}")
:::

:::warn
Debugging prints are scaffolding. Remove them when the bug is fixed, especially in exercises: the checks compare your **exact** output.
:::

If a loop runs too many times to read, print only some passes, or stop it early with a counter:

:::example title="Only watch the first few passes"
x = 1000
steps = 0
while x != 1:
    if steps < 5:
        print(f"{steps=} {x=}")
    if x % 2 == 0:
        x //= 2
    else:
        x = 3 * x + 1
    steps += 1
print("Reached 1 after", steps, "steps")
:::

## A catalogue of loop bugs

Almost every loop bug is one of these five. Learn their symptoms, and you'll know where to look.

| Bug | Symptom | Where to look |
|---|---|---|
| **Off by one** | One pass too many or too few; first or last value missing | `<` versus `<=`; the counter's starting value |
| **Bad start** | Answer is wrong by a fixed amount, or always 0 | The accumulator's starting value (0 for sums, 1 for products) |
| **Reset inside** | Only the last pass counts | An accumulator set to its start value inside the body |
| **Never ends** | The program hangs | The update: missing, wrong direction, skipped by `continue` or an `if` |
| **Never starts** | Nothing happens, no error | The condition is false at the first check |

:::example title="Spot the bug from its symptom"
count = 0
n = 1
while n < 10:
    count += 1
    n += 1
print("Counted", count, "numbers from 1 to 10")
:::

It claims to count 1 to 10 but prints 9. Symptom: one too few. Look at the comparison.

## Quiz

:::quiz id=quiz
- q: In a compact trace table for a while loop, when do you add a row?
  options: ["After every line", "Each time the condition is checked", "Only at the end", "When something prints"]
  answer: 1
  explain: "One row per check; the number of True rows is the number of passes."
- q: How many passes?
  code: |
    n = 1
    while n < 100:
        n *= 3
  type: text
  answer: ["5", "five"]
  explain: "n is 1, 3, 9, 27, 81 at the start of each pass; 243 ends it."
- q: What does this print?
  type: output
  code: |
    x = 10
    while x > 1:
        x //= 2
        print(x, end=" ")
  answer: "5 2 1 "
  explain: "10 // 2 is 5, then 2, then 1."
- q: What does `print(f"{n=}")` print when n is 4?
  type: text
  answer: ["n=4"]
  explain: "The = shortcut prints the expression, =, and its value."
- q: A loop that should total some numbers prints only the last number. Which bug?
  options: ["Off by one", "The accumulator is reset inside the loop", "Never ends", "Bad start value"]
  answer: 1
  explain: "Each pass starts the total again."
- q: A loop does nothing at all and there's no error. What's the likeliest cause?
  options: ["The condition is False at the first check", "A missing update", "A wrong start value for the total", "A syntax error"]
  answer: 0
  explain: "The body never runs."
- q: What is a loop invariant?
  options: ["A variable that never changes", "Something true every time the condition is checked", "A loop that never ends", "The loop's last value"]

  explain: "It describes what the variables mean at each check."
