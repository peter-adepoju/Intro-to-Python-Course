## Warm-up

:::predict
n = 2024
print(n % 10)
print(n // 10)
print(n % 100)
print(n // 100 % 10)
:::

`% 10` gives the last digit and `// 10` removes it. Those two operations are the start of everything today.

## Digits

To work with each digit of a number, peel them off from the right, one per pass, until nothing is left:

:::example title="Digits from right to left" try=4096
n = int(input("Number: "))
while n > 0:
    print(n % 10)
    n //= 10
:::

Everything you know about accumulators now applies. Here's the **sum of the digits**:

:::example title="Digit sum" try=4096
n = int(input("Number: "))
total = 0
while n > 0:
    total += n % 10
    n //= 10
print("Digit sum:", total)
:::

You can also build a number back up. Each new digit goes on the **right** of the number so far, which means "multiply by 10 and add the digit":

:::example title="Reverse a number" try=12345
n = int(input("Number: "))
backwards = 0
while n > 0:
    backwards = backwards * 10 + n % 10
    n //= 10
print(backwards)
:::

Step it in X-ray: `backwards` goes 5, 54, 543, 5432, 54321. This works with numbers only, no strings, which matters in languages where turning a number into text is expensive, and it's a favourite interview question.

:::note
You could get digits from `str(n)` instead, and often that's simpler. Doing it with arithmetic teaches you how numbers are built, and how base 10 works: each digit is worth ten times the one to its right.
:::

## Divisors

`d` is a **divisor** of `n` when `n % d == 0`. To find them all, try every candidate:

:::example title="All the divisors" try=36
n = int(input("Number: "))
d = 1
while d <= n:
    if n % d == 0:
        print(d, end=" ")
    d += 1
:::

A number is **perfect** if it equals the sum of its divisors other than itself: 6 = 1 + 2 + 3. There are very few. The next ones are 28, 496 and 8128.

:::example title="Is it perfect?" try=28
n = int(input("Number: "))
total = 0
d = 1
while d < n:
    if n % d == 0:
        total += d
    d += 1
print(n, "is perfect" if total == n else "is not perfect")
:::

## Prime numbers

A **prime** is a whole number greater than 1 whose only divisors are 1 and itself: 2, 3, 5, 7, 11, 13... Primes are the building blocks of all whole numbers, and they protect almost every secure connection on the internet.

To test a number, search for a divisor between 2 and `n - 1`. Finding one proves it isn't prime, so `break`. If the search finds nothing, it is:

:::example title="A first prime test" try=97
n = int(input("Number: "))
d = 2
while d < n:
    if n % d == 0:
        print(n, "is not prime: it divides by", d)
        break
    d += 1
else:
    if n > 1:
        print(n, "is prime")
    else:
        print(n, "is not prime")
:::

That's yesterday's `while ... else`: the `else` runs only if no divisor was found. Note the special case: 1 isn't prime, by definition, and neither is 0.

### Doing less work

For a big prime, that test tries every number below it. For 1,000,003 that's a million tries. But it doesn't need to.

Divisors come in **pairs**: if `d` divides `n`, then so does `n // d`. For 36 the pairs are 1 × 36, 2 × 18, 3 × 12, 4 × 9 and 6 × 6. In every pair, one number is **at most the square root** (6 for 36). So if `n` has any divisor besides 1 and itself, it has one no bigger than √n. You only need to search up to there.

You don't even need a square root function: `d * d <= n` says the same thing as `d <= √n`.

:::example title="Count the work" try=1000003
n = int(input("Number: "))
slow = 0
d = 2
while d < n:
    slow += 1
    if n % d == 0:
        break
    d += 1
fast = 0
d = 2
while d * d <= n:
    fast += 1
    if n % d == 0:
        break
    d += 1
print("Divisions tried, slow test:", slow)
print("Divisions tried, fast test:", fast)
:::

A million tries against a thousand. For numbers with 20 digits, the slow test would run for longer than you'll live, and the fast one finishes in seconds. Counting the steps an algorithm takes is how computer scientists compare algorithms, and you'll do it properly in Week 16.

:::key
To test whether `n` is prime, try divisors `d` from 2 while `d * d <= n`. If none divides `n` (and `n > 1`), it's prime.
:::

### A loop inside a loop

To list the primes up to 50, run the prime test on every number. That puts one loop **inside** another: for each `n`, the inner loop runs completely.

:::example title="Primes up to 50"
n = 2
while n <= 50:
    d = 2
    while d * d <= n:
        if n % d == 0:
            break
        d += 1
    else:
        print(n, end=" ")
    n += 1
:::

Notice where `d = 2` is: inside the outer loop, so the search starts again for every new `n`. Next week is all about loops inside loops.

## Euclid's algorithm

The **greatest common divisor** (gcd) of two numbers is the largest number that divides both. gcd(84, 36) is 12. You need it to simplify fractions: 36/84 is 3/7, dividing top and bottom by 12.

You could try every number from the smaller one downwards. Around 300 BC, Euclid of Alexandria wrote down something far faster. It rests on one fact: **gcd(a, b) is the same as gcd(b, a % b)**. Replace the pair with that, again and again, until the second number is 0. Then the first number is the answer.

:::example title="Euclid's algorithm" try=84,36
a = int(input("a: "))
b = int(input("b: "))
while b != 0:
    a, b = b, a % b
print("gcd:", a)
:::

Three lines of loop, and it's one of the oldest algorithms still in daily use: it runs inside the encryption that secures your web browser. The figure shows why it works. Cut the biggest squares you can from an `a` by `b` rectangle, then do the same with the strip that's left over. The last square fits both sides exactly:

:::widget euclid caption="Each colour is one step of the algorithm. The table shows the same steps as arithmetic. Try 21, 13: consecutive Fibonacci numbers make Euclid take the most steps."
{"a": 84, "b": 36}
:::

The **lowest common multiple** (lcm) is the smallest number both divide into. It comes straight from the gcd: `lcm(a, b) = a * b // gcd(a, b)`. For 4 and 6: 24 // 2 = 12.

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: Goldbach's conjecture"
In 1742 Christian Goldbach guessed that **every even number greater than 2 is the sum of two primes**: 28 = 5 + 23. Nobody has ever proved it, but computers have checked it far beyond a billion billion.

Ask for an even number with the prompt `Even number: `. Find the pair of primes with the **smallest** first prime, and print it like `28 = 5 + 23`. If the number is odd or less than 4, print `Please type an even number above 2`.
@@starter

@@tests
def test_cases():
    "several numbers"
    for n, p in [(4, 2), (28, 5), (100, 3), (98, 19), (10, 3), (1000000, 17)]:
        expect_output(f"Even number: {n}\n{n} = {p} + {n - p}", inputs=[str(n)], echo=True)
def test_bad():
    "odd and small numbers"
    expect_output("Even number: 15\nPlease type an even number above 2", inputs=["15"], echo=True)
    expect_output("Even number: 2\nPlease type an even number above 2", inputs=["2"], echo=True)
@@hint
Try each `p` from 2 upwards. For each, you need two prime tests: one on `p` and one on `n - p`. Stop at the first `p` where both pass.
@@hint
Without functions (they're Week 6), you have to write the prime test out twice inside the loop. That's fine for now. Notice how much you'd like to give it a name.
@@solution
n = int(input("Even number: "))
if n < 4 or n % 2 != 0:
    print("Please type an even number above 2")
else:
    p = 2
    while True:
        p_prime = p > 1
        d = 2
        while d * d <= p:
            if p % d == 0:
                p_prime = False
                break
            d += 1
        q = n - p
        q_prime = q > 1
        d = 2
        while d * d <= q:
            if q % d == 0:
                q_prime = False
                break
            d += 1
        if p_prime and q_prime:
            print(f"{n} = {p} + {q}")
            break
        p += 1
:::
