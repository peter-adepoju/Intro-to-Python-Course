## Warm-up

:::predict
n = 3
n = n + 1
n = n + 1
if n > 4:
    print("big", n)
else:
    print("small", n)
:::

Notice the repetition in that program: `n = n + 1` twice. Imagine needing it a thousand times. Today you'll learn to write it once and tell Python how often to repeat it.

## Why loops?

Print the numbers 1 to 5:

:::example title="Without a loop"
print(1)
print(2)
print(3)
print(4)
print(5)
:::

That works for 5. For 500 it would be absurd, and if the user chose the number, it would be impossible: you can't know in advance how many lines to write. A **loop** runs the same lines over and over, as many times as needed.

:::example title="With a loop"
n = 1
while n <= 5:
    print(n)
    n = n + 1
:::

Change the `5` to `500` and run it again. Same three lines, a hundred times the work.

## How while works

```python
while n <= 5:
    print(n)
    n = n + 1
```

A `while` loop looks like an `if`: a condition, a colon, and an indented block called the **body**. The difference is what happens after the body:

1. Check the condition.
2. If it's `False`, skip the body and carry on after the loop. The loop is over.
3. If it's `True`, run the body, then **go back to step 1**.

So the body keeps running *while* the condition stays true. Press X-ray on the loop above and step through. Watch the yellow line jump back up to the `while` line after every pass, and watch `n` grow.

Each pass through the body is called an **iteration**. The table below is what you'd write if you traced it by hand: one row per line Python runs, with every variable's value after that line. Press **Next row**, and predict each row before it appears.

:::widget tracetable caption="One row per line run. The condition column shows the loop's question each time Python asks it. Bold values just changed."
{"code": "n = 1\nwhile n <= 3:\n    print(n)\n    n = n + 1\nprint('done')"}
:::

Look at the last check of the condition: `n` is 4, `4 <= 3` is `False`, and only then does the loop end. The condition is checked one more time than the body runs.

:::key
`while` checks its condition **before** every pass. If the condition is false the very first time, the body never runs at all.
:::

:::example title="Zero iterations"
n = 10
while n <= 5:
    print("This never prints")
    n = n + 1
print("Finished, n is", n)
:::

## Counting loops: three parts

Almost every counting loop has the same three parts. Learn to see them:

```python
n = 1              # 1. start: give the counter its first value
while n <= 5:      # 2. condition: keep going while this is true
    print(n)
    n = n + 1      # 3. update: move the counter towards the end
```

Change any part and the loop changes:

:::example title="Count down"
n = 5
while n >= 1:
    print(n)
    n -= 1
print("Lift off!")
:::

:::example title="Count in twos"
n = 0
while n <= 10:
    print(n)
    n += 2
:::

:::example title="Count up to a number the user chooses" try=4
limit = int(input("Up to: "))
n = 1
while n <= limit:
    print(n)
    n += 1
:::

:::predict
i = 2
while i < 20:
    print(i)
    i *= 3
:::

The update doesn't have to be `+ 1`. It just has to move the counter towards making the condition false.

## How many times does it run?

Two loops that look almost the same:

:::example
n = 1
while n < 5:
    print(n, end=" ")
    n += 1
print()
n = 1
while n <= 5:
    print(n, end=" ")
    n += 1
:::

The first runs 4 times, the second 5. A useful rule for counting up by 1:

- `while n < stop:` starting from `start` runs `stop - start` times;
- `while n <= stop:` runs `stop - start + 1` times.

Getting this wrong by one is called an **off-by-one error**: the loop runs once too often or once too few. It's the loop version of the boundary bugs you met last week, and you'll meet it for the rest of your programming life. The cure is the same: check the first and the last iteration by hand.

:::tip
To check a loop, ask three questions. What is the counter on the **first** pass? What is it on the **last** pass? What is it **after** the loop?
:::

## Infinite loops

If the condition never becomes false, the loop never ends. This is an **infinite loop**:

```python
n = 1
while n <= 5:
    print(n)
```

The update is missing, so `n` stays 1 forever and Python prints 1 forever. Infinite loops are the most common loop bug. Their usual causes:

- **No update**: the counter never changes.
- **Update in the wrong direction**: `n -= 1` when the condition waits for `n` to get big.
- **Update skipped**: the update sits inside an `if` that doesn't always run.
- **A condition that can't fail**: `while n != 10` with `n += 3` from 0 jumps straight past 10.

:::example title="Run this: the site will stop it" forever=yes
n = 0
while n != 10:
    n += 3
:::

Nothing is printed and nothing seems to happen. On this site, a program that runs for more than 10 seconds is stopped for you, with a message. In other places, you stop a running program by pressing **Ctrl** + **C**.

:::mistake
`while n != 10` is risky. If `n` can skip over 10, the loop never ends. Prefer `while n < 10`, which ends however `n` gets past the line.
:::

## Decisions inside loops

The body of a loop can hold anything, including an `if`. The `if` is checked on every pass:

:::example title="Only the multiples of 3"
n = 1
while n <= 20:
    if n % 3 == 0:
        print(n)
    n += 1
:::

Notice the indentation: `print(n)` is inside the `if`, which is inside the loop. The update `n += 1` is in the loop but **not** in the `if`, so it happens on every pass. If you indented it under the `if` by mistake, `n` would get stuck at 1 and you'd have an infinite loop.

:::example title="Counting the ones that match"
n = 1
count = 0
while n <= 100:
    if n % 7 == 0:
        count += 1
    n += 1
print(count, "multiples of 7 from 1 to 100")
:::

Here `count` is a second counter. It only goes up when something interesting happens. You'll build on this idea tomorrow.

## The counter after the loop

When the loop ends, the counter keeps its last value, and that value is often useful:

:::example title="How many doublings to pass 1000?"
value = 1
steps = 0
while value <= 1000:
    value *= 2
    steps += 1
print(steps, "doublings reach", value)
:::

## Quiz

:::quiz id=quiz
- q: When does a while loop check its condition?
  options: ["Once, at the start", "Before every pass through the body", "After every pass only", "At the end"]
  answer: 1
  explain: "Check, body, check, body... until the check is False."
- q: What does this print?
  type: output
  code: |
    n = 1
    while n < 4:
        print(n)
        n += 1
  answer: "1\n2\n3"
  explain: "When n becomes 4, 4 < 4 is False."
- q: How many times does the body run?
  code: |
    n = 0
    while n < 7:
        n += 1
  type: text
  answer: ["7", "seven"]
  explain: "n is 0 to 6 at the start of each pass."
- q: What does this print?
  type: output
  code: |
    n = 10
    while n < 5:
        n += 1
    print(n)
  answer: "10"
  explain: "The condition is False straight away; the body never runs."
- q: Why does this never end?
  code: |
    n = 1
    while n <= 5:
        print(n)
  options: ["The condition is wrong", "n never changes", "print can't be in a loop", "It does end"]
  answer: 1
  explain: "No update, so n <= 5 stays True."
- q: What is n after this loop?
  code: |
    n = 0
    while n < 10:
        n += 3
  type: text
  answer: "12"
  explain: "n goes 3, 6, 9, 12, and 12 < 10 is False."
- q: What stops a running program in most terminals?
  options: ["Ctrl + Z", "Ctrl + C", "Escape", "Ctrl + S"]
  answer: 1
  explain: "Ctrl + C interrupts it."
- q: Which condition is safer for a counter that goes up in steps of 3 to reach 20?
  options: ["`while n != 20:`", "`while n < 20:`"]
  answer: 1
  explain: "n might jump past 20 and never equal it."
- q: What does this print?
  type: output
  code: |
    n = 1
    count = 0
    while n <= 10:
        if n % 4 == 0:
            count += 1
        n += 1
    print(count)
  answer: "2"
  explain: "4 and 8."
- q: What is one pass through a loop body called?
  type: text
  answer: ["iteration", "an iteration"]
  explain: "Each repetition is an iteration."
:::
