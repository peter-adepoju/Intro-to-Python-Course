## How to review

Rereading your notes feels productive, but it mostly creates a feeling of familiarity, not the ability to use what you read. What actually works is **retrieval practice**: trying to recall or use something **before** you look at it. Getting it wrong and then checking is part of how it works.

So today, for every section:

1. Try each prediction **before** running it, and write your guess down.
2. If you get one wrong, work out exactly why before moving on.
3. Keep a list of anything that surprised you. That list is your revision plan for the exam.

## Values, types and strings

Week 1's ideas in brief: every value has a **type** (`int`, `float`, `str`, `bool`); operators behave differently for different types; a variable is a **name** for a value, and assignment moves the name; strings are sequences you can index and slice; `input` always gives a string.

:::predict
print(7 / 2, 7 // 2, 7 % 2, -7 // 2)
:::

:::predict
print(2 ** 3 ** 2, (2 ** 3) ** 2)
:::

:::predict
print(0.1 + 0.2 == 0.3, round(0.1 + 0.2, 2) == 0.3)
:::

:::predict
x = 5
y = x
x = x + 1
print(x, y)
:::

:::predict
s = "Python"
print(s[0], s[-1], s[1:4], s[::-1], s[10:])
:::

:::predict
print("3" + "4", 3 + 4, "3" * 4, int("3") * 4)
:::

:::predict
price = 1234.5
print(f"{price:,.2f}|{price:>10.1f}|{'hi':^6}|")
:::

:::key
`/` always gives a float; `//` rounds **down** (towards minus infinity, so `-7 // 2` is `-4`). Floats are approximate, so compare them with `round` or a tolerance. Assignment never links two names: `y = x` copies the **reference**, and rebinding `x` later doesn't touch `y`.
:::

## Decisions

Week 2: comparisons give booleans; `and`, `or` and `not` combine them; `if`, `elif` and `else` choose **one** branch, checked from the top.

:::predict
age = 17
print(age >= 18 or age > 16 and False)
print(not age == 17)
:::

:::predict
mark = 75
if mark >= 50:
    print("pass")
elif mark >= 70:
    print("merit")
else:
    print("fail")
:::

:::predict
x = 0
print(x == 0 or 1 / x > 2)
:::

:::predict
print(bool(""), bool("0"), bool(0), bool([]), bool(" "))
:::

:::key
`and` binds tighter than `or`. In an `elif` chain only the **first** true branch runs, so put the most specific test first. `and` and `or` **short-circuit**: the right side isn't evaluated if the left side already decides the answer, which is why `x == 0 or 1 / x > 2` doesn't crash. Empty things and zero are false; everything else is true, including `"0"`.
:::

## Loops

Weeks 3 and 4: `while` repeats while a condition is true; `for` goes through a sequence; `range(start, stop, step)` stops **before** `stop`; `break` leaves a loop, `continue` skips to the next round; nested loops run the inner loop completely for each round of the outer one.

:::predict
n = 10
steps = 0
while n != 1:
    n = n // 2 if n % 2 == 0 else 3 * n + 1
    steps += 1
print(steps)
:::

:::predict
print(list(range(5)), list(range(2, 10, 3)), list(range(5, 0, -2)))
:::

:::predict
for i in range(1, 4):
    for j in range(i):
        print(i, end="")
    print()
:::

:::predict
total = 0
for n in range(10):
    if n % 3 == 0:
        continue
    if n > 7:
        break
    total += n
print(total)
:::

:::widget tracetable caption="Trace the last prediction one line at a time, if you got it wrong. Watch n, total and the conditions."
{"code": "total = 0\nfor n in range(10):\n    if n % 3 == 0:\n        continue\n    if n > 7:\n        break\n    total += n\nprint(total)"}
:::

:::key
Every loop needs a reason to stop. With `while`, something in the body must change the condition. Off-by-one errors live in `range`'s stop value and in `<` versus `<=`: test the smallest cases (0, 1 and 2 items) by hand.
:::

## The classic mistakes

These are the mistakes that every beginner makes, and that still trip up experienced programmers when they're tired. For each, can you say **why** it goes wrong?

| Mistake | What happens | The fix |
|---|---|---|
| `age = input("Age: ")` then `age + 1` | `TypeError`: input gives a string | `int(input(...))` |
| `if x = 5:` | `SyntaxError`: `=` assigns | `==` compares |
| `if answer == "yes" or "y":` | always true: `"y"` on its own is truthy | `answer in ("yes", "y")` |
| `while n > 0:` with no change to `n` | runs for ever | change `n` in the body |
| `for i in range(1, 10)` to mean 1 to 10 | stops at 9 | `range(1, 11)` |
| `total = 0` inside the loop | resets every time | set it once, before the loop |
| `print` in a function instead of `return` | the caller gets `None` | `return` the value |
| `0.1 * 3 == 0.3` | `False`: floats are approximate | `round` or `abs(a - b) < 1e-9` |

:::example
answer = "no"
if answer == "yes" or "y":
    print("This always runs!")
if answer in ("yes", "y"):
    print("This doesn't.")
:::

:::exercise id=change points=10 title="Change from a note"
Write `change(paid, cost)` that returns the change in the fewest notes and coins, as a dictionary from denomination to how many, using naira denominations 1000, 500, 200, 100, 50, 20, 10, 5 and 1. Leave out denominations not used. Raise a `ValueError` if `paid` is less than `cost`.
@@starter
DENOMS = [1000, 500, 200, 100, 50, 20, 10, 5, 1]

@@tests
def test_values():
    "several"
    assert change(5000, 3215) == {1000: 1, 500: 1, 200: 1, 50: 1, 20: 1, 10: 1, 5: 1}
    assert change(100, 100) == {}
    assert change(2000, 1) == {1000: 1, 500: 1, 200: 2, 50: 1, 20: 2, 5: 1, 1: 4}
    try:
        change(10, 20)
    except ValueError:
        pass
    else:
        raise AssertionError("paying too little should raise a ValueError")
@@solution
DENOMS = [1000, 500, 200, 100, 50, 20, 10, 5, 1]

def change(paid, cost):
    if paid < cost:
        raise ValueError("not enough paid")
    left = paid - cost
    result = {}
    for d in DENOMS:
        count, left = divmod(left, d)
        if count:
            result[d] = count
    return result
:::

:::exercise id=digits points=10 title="Digit sum, the long way"
Without turning the number into a string, write `digit_sum(n)` that adds up the digits of a whole number, using `%` and `//` in a `while` loop. Negative numbers use their digits too.
@@starter

@@tests
def test_values():
    "several"
    assert digit_sum(2026) == 10
    assert digit_sum(0) == 0
    assert digit_sum(-405) == 9
    assert "str(" not in source
@@solution
def digit_sum(n):
    n = abs(n)
    total = 0
    while n > 0:
        total += n % 10
        n //= 10
    return total

:::exercise id=triangle points=10 title="A number triangle"
Write `triangle(n)` that returns, as one string with lines joined by `"\n"`, a triangle of `n` rows where row `r` (from 1) holds the numbers 1 to `r` separated by spaces, centred in the width of the last row.
@@starter

@@tests
def test_values():
    "several sizes"
    assert triangle(3) == "  1\n 1 2\n1 2 3"
    assert triangle(1) == "1"
    assert triangle(0) == ""
@@hint
The last row is `" ".join(str(i) for i in range(1, n + 1))`; its length is the width. `row.center(width)` centres, then `rstrip()` removes the spaces on the right.
@@solution
def triangle(n):
    rows = [" ".join(str(i) for i in range(1, r + 1)) for r in range(1, n + 1)]
    if not rows:
        return ""
    width = len(rows[-1])
    return "\n".join(row.center(width).rstrip() for row in rows)
:::

:::exercise id=primes points=10 title="Primes below n"
Write `primes_below(n)` that returns a list of the primes less than `n`, testing each number with trial division up to its square root.
@@starter

@@tests
def test_values():
    "several"
    assert primes_below(20) == [2, 3, 5, 7, 11, 13, 17, 19]
    assert primes_below(2) == []
    assert len(primes_below(1000)) == 168
@@solution
def is_prime(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True

def primes_below(n):
    return [k for k in range(n) if is_prime(k)]
:::

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: Roman numerals"
Write `to_roman(n)` for 1 to 3999 (raise a `ValueError` otherwise), and `from_roman(text)` that converts back, raising a `ValueError` for anything that isn't the standard way of writing a number (so `"IIII"`, `"VX"` and `"ABC"` are rejected). The standard form uses `M D C L X V I` with subtractive pairs `CM CD XC XL IX IV`.

```
to_roman(2026)       ->  "MMXXVI"
from_roman("XLII")   ->  42
```
@@starter

@@tests
def bad(fn, arg):
    try:
        fn(arg)
    except ValueError:
        return
    raise AssertionError(f"{fn.__name__}({arg!r}) should raise a ValueError")
def test_to():
    "to_roman"
    assert to_roman(2026) == "MMXXVI"
    assert to_roman(1994) == "MCMXCIV"
    assert to_roman(3999) == "MMMCMXCIX"
    assert to_roman(4) == "IV"
    bad(to_roman, 0)
    bad(to_roman, 4000)
def test_from():
    "from_roman"
    assert from_roman("XLII") == 42
    assert from_roman("MCMXCIV") == 1994
    assert all(from_roman(to_roman(n)) == n for n in range(1, 4000))
    for t in ["IIII", "VX", "ABC", "", "IC", "MMMM"]:
        bad(from_roman, t)
@@hint
List the values with their symbols from largest to smallest, including the pairs: `[(1000, "M"), (900, "CM"), (500, "D"), ...]`. To convert, take as many of each as fit.
@@hint
For `from_roman`, the easiest strict check: work out the number however you like, then check that `to_roman` of it gives back exactly the same text.
@@solution
PAIRS = [(1000, "M"), (900, "CM"), (500, "D"), (400, "CD"), (100, "C"), (90, "XC"),
         (50, "L"), (40, "XL"), (10, "X"), (9, "IX"), (5, "V"), (4, "IV"), (1, "I")]

def to_roman(n):
    if not 1 <= n <= 3999:
        raise ValueError(f"can't write {n} in Roman numerals")
    out = ""
    for value, symbol in PAIRS:
        while n >= value:
            out += symbol
            n -= value
    return out

def from_roman(text):
    total, i = 0, 0
    while i < len(text):
        found = False
        for value, symbol in PAIRS:
            if text.startswith(symbol, i):
                total += value
                i += len(symbol)
                found = True
                break
        if not found:
            raise ValueError(f"not a Roman numeral: {text!r}")
    if not 1 <= total <= 3999 or to_roman(total) != text:
        raise ValueError(f"not a Roman numeral: {text!r}")
    return total
:::
