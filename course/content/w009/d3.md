## Warm-up

:::predict
a, b = 1, 2
a, b = b, a
print(a, b)
def low_high(x, y):
    return min(x, y), max(x, y)
print(low_high(9, 4))
:::

You've used tuples since Week 1 without knowing their name. `1, 2` is a tuple; swapping builds one; a function returning two values returns one. The last line shows it, in round brackets.

## What a tuple is

A **tuple** is an ordered sequence, like a list, written with round brackets:

:::example
point = (3, 4)
date = (2026, 10, 27)
mixed = ("Ada", 36, True)
print(point[0], date[-1], mixed[1:])
print(len(date), type(point))
:::

Indexing, slicing, `len`, `in`, `for`, `+` and `*` all work as they do for lists and strings.

Actually, it's the **commas** that make a tuple, not the brackets. The brackets are only needed when the tuple would otherwise be unclear:

:::example
t = 1, 2, 3
print(t)
print(type(t))
:::

### One item and no items

Because the comma makes the tuple, a tuple with one item needs a comma after it:

:::example
not_a_tuple = (5)
one = (5,)
empty = ()
print(type(not_a_tuple), type(one), len(empty))
:::

`(5)` is just the number 5 in brackets, like `(2 + 3)`. `(5,)` is a tuple holding 5.

### Tuples can't be changed

A tuple is **immutable**, like a string. Once it's made, its items can't be replaced, added or removed:

:::example error=yes
point = (3, 4)
point[0] = 10
:::

So tuples have only two methods, `count` and `index`, the ones that don't change anything:

:::example
votes = ("yes", "no", "yes", "yes")
print(votes.count("yes"), votes.index("no"))
:::

To "change" a tuple, make a new one, just as with strings:

:::example
point = (3, 4)
point = (10,) + point[1:]
print(point)
:::

:::warn
A tuple's slots can't be pointed elsewhere, but if one of its items is a **list**, that list can still be changed. `t = ([1], [2])` then `t[0].append(5)` works: the tuple still holds the same two lists; one of them just has more in it.
:::

## Tuples or lists?

Both hold sequences. Choose by what the data **is**:

| Use a tuple when... | Use a list when... |
|---|---|
| the group has a **fixed** size and meaning: `(x, y)`, `(year, month, day)`, `(name, score)` | you'll **add or remove** items |
| the values shouldn't change | items are all the same kind of thing, in any number |
| you're returning several values from a function | you'll sort it in place, or change items |

A good rule of thumb: a **list** is like a column in a table (many values of the same kind), and a **tuple** is like a row (one record, with a fixed meaning for each position).

Immutability is also a guarantee. If you give a tuple to a function, you know for certain it comes back unchanged: none of last week's aliasing surprises can happen. And in Week 10 you'll see that tuples can be used as dictionary keys, which lists can't.

## Unpacking

**Unpacking** pulls a sequence apart into separate names, in one assignment:

:::example
point = (3, 4)
x, y = point
print(x, y)
name, age, city = ["Ada", 36, "London"]
print(name, city)
first, second, third = "abc"
print(third)
:::

It works with any sequence: tuples, lists, strings, `split` results. There must be exactly as many names as items:

:::example error=yes
x, y = (1, 2, 3)
:::

### Unpacking in a for loop

When a list holds pairs, you can unpack each pair as the loop takes it:

:::example
scores = [("Ada", 93), ("Grace", 88), ("Alan", 97)]
for name, score in scores:
    print(f"{name} scored {score}")
:::

This is far easier to read than `s[0]` and `s[1]` everywhere.

### A starred name takes the rest

Put a `*` before one name, and it collects all the items the others don't take, as a list:

:::example
first, *rest = [1, 2, 3, 4, 5]
print(first, rest)
*start, last = "hello"
print(start, last)
head, *middle, tail = (10, 20, 30, 40)
print(head, middle, tail)
:::

### Nested unpacking

If the items are themselves sequences, the names can be nested to match:

:::example
record = ("Ada", (1815, 12, 10))
name, (year, month, day) = record
print(name, year)
:::

:::key
`a, b = sequence` unpacks a sequence into names; the counts must match. A `*name` collects any extra items into a list. Unpacking works in assignments and in `for` loops.
:::

## Tuples in functions, sorting and records

### Several return values

`return a, b` returns one tuple, which the caller usually unpacks straight away:

:::example
def stats(values):
    return min(values), max(values), sum(values) / len(values)

low, high, mean = stats([4, 8, 15, 16, 23, 42])
print(low, high, mean)
result = stats([1, 2])
print(result)
:::

### Comparing tuples

Tuples compare item by item from the left, just like words compare letter by letter. That's why they make perfect sort keys, as you saw yesterday:

:::example
print((1, 2) < (1, 3))
print((2, 0) > (1, 99))
print(sorted([(2, "b"), (1, "z"), (2, "a")]))
:::

### Tuples as records

A list of tuples is a simple table. Each tuple is a row, and each position has a meaning:

:::example
cities = [("Lagos", 15.4), ("Cairo", 22.2), ("Kinshasa", 17.0), ("Luanda", 9.3)]
biggest = max(cities, key=lambda c: c[1])
name, millions = biggest
print(f"{name}: {millions} million")
for name, pop in sorted(cities, key=lambda c: -c[1]):
    print(f"{name:<10}{pop:>6.1f}")
:::

In Phase 3 you'll learn **named tuples** and **classes**, which let you write `city.name` instead of `city[0]`. For now, unpacking into well-named variables keeps the code readable.

:::exercise id=min_max points=10 title="Two values back"
Write `bounds(values)` that returns a tuple `(smallest, largest)` for a non-empty list, in one pass, without `min` or `max`. Then print `Range: 4 to 42` for the list `[15, 4, 42, 16]`, unpacking the result.
@@starter

@@tests

    "bounds"
    assert bounds([15, 4, 42, 16]) == (4, 42)
    assert bounds([7]) == (7, 7)
    assert "min(" not in source and "max(" not in source
def test_output():
    "the printed line"
    expect_output("Range: 4 to 42")
@@solution
def bounds(values):
    lo = hi = values[0]
    for v in values[1:]:
        if v < lo:
            lo = v
        if v > hi:
            hi = v
    return lo, hi

lo, hi = bounds([15, 4, 42, 16])
print(f"Range: {lo} to {hi}")

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: the closest pair"
Write `closest_pair(points)` where `points` is a list of `(x, y)` tuples (at least two). Return a tuple `(p, q, d)`: the two points that are closest together, in the order they appear in the list, and their distance rounded to 3 places. If several pairs are equally close, return the first pair found by checking pairs in order (point 0 with 1, 2, 3..., then point 1 with 2, 3..., and so on).

Then read points with the prompt `Point (x y): ` until a blank line, and print `Closest: (1, 2) and (2, 2), distance 1.0`.
@@starter

@@tests
def test_function():
    "closest_pair"
    assert closest_pair([(0, 0), (5, 5), (1, 1), (9, 9)]) == ((0, 0), (1, 1), 1.414)
    assert closest_pair([(0, 0), (3, 4)]) == ((0, 0), (3, 4), 5.0)
    assert closest_pair([(0, 0), (1, 0), (5, 0), (6, 0)]) == ((0, 0), (1, 0), 1.0), "A tie: the first pair found wins."
def test_program():
    "the program"
    expect_output("Point (x y): 1 2\nPoint (x y): 7 7\nPoint (x y): 2 2\nPoint (x y): \nClosest: (1, 2) and (2, 2), distance 1.0",
                  inputs=["1 2", "7 7", "2 2", ""], echo=True)
@@hint
Two nested loops, the inner one starting at `i + 1`, with a best-so-far for the distance. Use `<` (not `<=`) so the first of equal pairs is kept.
@@solution
def closest_pair(points):
    best = None
    for i in range(len(points)):
        for j in range(i + 1, len(points)):
            (x1, y1), (x2, y2) = points[i], points[j]
            d = ((x2 - x1) ** 2 + (y2 - y1) ** 2) ** 0.5
            if best is None or d < best[2]:
                best = (points[i], points[j], d)
    p, q, d = best
    return p, q, round(d, 3)

points = []
while True:
    line = input("Point (x y): ")
    if line == "":
        break
    x, y = line.split()
    points.append((int(x), int(y)))
p, q, d = closest_pair(points)
print(f"Closest: {p} and {q}, distance {d}")
:::
