:::exercise id=mix_merge3 points=10 title="Merge three"
Write `merge3(a, b, c)` that merges three sorted lists into one sorted list in a single pass, taking the smallest of the three front items each time (ties go to `a`, then `b`). Don't use `sort`, `sorted`, `min` or `heapq`.
@@starter

@@tests
def test_values():
    "several"
    assert merge3([1, 5], [2, 6], [3, 4]) == [1, 2, 3, 4, 5, 6]
    assert merge3([], [], []) == [] and merge3([1], [], [0]) == [0, 1]
    a, b, c = [(1, "a"), (2, "a")], [(1, "b")], [(1, "c"), (3, "c")]
    assert merge3(a, b, c) == [(1, "a"), (1, "b"), (1, "c"), (2, "a"), (3, "c")]
    import re
    assert not re.search(r"\bsorted\(|\.sort\(|(?<![\w.])min\(|heapq", source)
@@hint
Keep `i, j, k`. Each round, look at whichever front items exist; pick the smallest with `<` comparisons in the order a, b, c so ties stay stable.
@@solution
def merge3(a, b, c):
    lists = [a, b, c]
    pos = [0, 0, 0]
    out = []
    while True:
        best = None
        for t in range(3):
            if pos[t] < len(lists[t]):
                if best is None or lists[t][pos[t]] < lists[best][pos[best]]:
                    best = t
        if best is None:
            return out
        out.append(lists[best][pos[best]])
        pos[best] += 1
:::

def second_highest(marks):
    counts = [0] * 101
    for m in marks:
        counts[m] += 1
    seen = 0
    for v in range(100, -1, -1):
        if counts[v]:
            seen += 1
            if seen == 2:
                return v
    return None

def standings(players):
    def pct(p):
        games = p[1] + p[2]
        return p[1] / games if games else 0
    return [p[0] for p in sorted(players, key=lambda p: (-pct(p), -p[1], p[0].lower()))]

def three_smallest(items):
    a = b = c = float("inf")
    for x in items:
        if x < a:
            a, b, c = x, a, b
        elif x < b:
            b, c = x, b
        elif x < c:
            c = x
    return [a, b, c]

## Forge: a smart sort

No single sort is best for every input. A tiny list is fastest with insertion sort. Whole numbers in a small range can be counted. Data that's already mostly in order can be merged run by run. Everything else wants a good general sort. Real libraries make choices like these all the time.

:::exercise id=forge points=50 title="Forge: a smart sort"
Write each algorithm as a function that takes a list and returns a **new** sorted list (the input unchanged), none of them using `sort` or `sorted`:

1. `insertion_sort(items)`
2. `merge_sort(items)`: stable, top-down.
3. `quick_sort(items)`: random pivot, three-way partition (so repeated values are fast). It may use list comprehensions or work in place on a copy.
4. `counting_sort(items)`: whole numbers only, any sign (shift by the smallest).
5. `run_count(items)`: how many non-decreasing runs the list has (0 for an empty list).

Then `smart_sort(items)` returns `(sorted_list, name)`, choosing in this order:

- fewer than 20 items: `"insertion"`;
- all items are whole numbers (`type(x) is int`) and `max - min` is at most `2 * len(items)`: `"counting"`;
- at most `len(items) // 50 + 1` runs (the data is mostly in order): `"merge"` (merge sort is fine here; a real library would merge the runs directly);
- otherwise: `"quick"`.
@@starter
import random

@@tests
import random as rnd
r = rnd.Random(19)
def check(f):
    cases = [[], [1], [2, 1], [3, 3, 3], list(range(50)), list(range(50, 0, -1)),
             [r.randint(-50, 50) for _ in range(300)], [r.random() for _ in range(300)],
             ["pear", "fig", "apple", "fig"]]
    for c in cases:
        if f is counting_sort and c and type(c[0]) is not int:
            continue
        before = list(c)
        assert f(c) == sorted(c), (f.__name__, c[:10])
        assert c == before, f.__name__ + " changed its input"

    "the four sorts"
    for f in (insertion_sort, merge_sort, quick_sort, counting_sort):
        check(f)
    recs = [(r.randint(0, 5), i) for i in range(200)]
    assert merge_sort(recs) == sorted(recs)
def test_runs():
    "run_count"
    assert run_count([]) == 0 and run_count([1, 2, 3]) == 1 and run_count([3, 2, 1]) == 3
    assert run_count([1, 5, 2, 6, 3]) == 3

    assert smart_sort([3, 1, 2]) == ([1, 2, 3], "insertion")
    marks = [r.randint(0, 100) for _ in range(500)]

    nearly = list(range(0, 2000, 2)) + list(range(1, 2000, 2))
    nearly = [x * 1000 for x in nearly]
    assert smart_sort(nearly) == (sorted(nearly), "merge")
    big = [r.randint(0, 10 ** 9) for _ in range(5000)]
    assert smart_sort(big) == (sorted(big), "quick")
    words = [r.choice(["kiwi", "fig", "date", "lime"]) for _ in range(300)]
    assert smart_sort(words) == (sorted(words), "quick")
    same = [7] * 20_000
    assert smart_sort(same)[1] == "counting"

    import re

@@hint
For `quick_sort` with comprehensions: pick `pivot = random.choice(items)`, split into `less`, `equal`, `more`, and return `quick_sort(less) + equal + quick_sort(more)`. Equal items never recurse, so all-equal lists are fast.
@@hint
`smart_sort` checks are cheap: one pass to test the types, `min` and `max` (allowed here), and one pass to count runs. Check them in the order given.
@@solution
import random

def insertion_sort(items):
    out = list(items)
    for i in range(1, len(out)):
        x, j = out[i], i - 1
        while j >= 0 and out[j] > x:
            out[j + 1] = out[j]
            j -= 1
        out[j + 1] = x
    return out

def merge_sort(items):
    if len(items) <= 1:
        return list(items)
    mid = len(items) // 2
    a, b = merge_sort(items[:mid]), merge_sort(items[mid:])
    out, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if b[j] < a[i]:
            out.append(b[j])
            j += 1
        else:
            out.append(a[i])
            i += 1
    return out + a[i:] + b[j:]

def quick_sort(items):
    if len(items) <= 1:
        return list(items)
    pivot = random.choice(items)
    less = [x for x in items if x < pivot]
    equal = [x for x in items if x == pivot]
    more = [x for x in items if pivot < x]
    return quick_sort(less) + equal + quick_sort(more)

def counting_sort(items):
    if not items:
        return []
    low, high = min(items), max(items)
    counts = [0] * (high - low + 1)
    for x in items:
        counts[x - low] += 1
    out = []
    for offset, c in enumerate(counts):
        out.extend([offset + low] * c)
    return out

def run_count(items):
    if not items:
        return 0
    return 1 + sum(1 for i in range(1, len(items)) if items[i] < items[i - 1])

def smart_sort(items):
    n = len(items)
    if n < 20:
        return insertion_sort(items), "insertion"
    if all(type(x) is int for x in items) and max(items) - min(items) <= 2 * n:
        return counting_sort(items), "counting"
    if run_count(items) <= n // 50 + 1:
        return merge_sort(items), "merge"
    return quick_sort(items), "quick"
:::

:::think title="Cheap checks, big savings"
Each check in `smart_sort` costs one pass over the data, O(n), and can save far more: counting instead of comparing, or a handful of merges instead of a full sort. Timsort's run detection is the same idea built into the sort itself. Whenever data might have structure (a small range, existing order, many repeats), a quick look before choosing an algorithm often pays for itself many times over.
:::

## Forge bonus: bucket sort

Counting sort needs whole numbers in a small range. **Bucket sort** handles decimal numbers spread fairly evenly over a known range, such as random numbers from 0 to 1. Make n buckets, each covering an equal slice of the range; drop each number into its bucket; sort each bucket (they're small, so insertion sort is ideal); and join the buckets in order.

If the numbers are spread evenly, each bucket gets about one number, and the whole sort is **O(n) on average**. If they all land in one bucket, it's as slow as insertion sort on everything: O(n²).

:::exercise id=forge2 points=30 title="Forge bonus: bucket sort"
Write `bucket_sort(items, low=0.0, high=1.0)` that sorts numbers in the range `low <= x < high` (the value `high` itself may also appear and goes in the last bucket) using `len(items)` buckets and insertion sort inside each bucket. Also write `bucket_sizes(items, low=0.0, high=1.0)` that returns the list of how many items fell in each bucket, so you can see how evenly they spread. Don't use `sort` or `sorted`.
@@starter

@@tests
import random
def test_values():
    "sorts"
    assert bucket_sort([0.42, 0.32, 0.23, 0.52, 0.25, 0.47, 0.51]) == sorted([0.42, 0.32, 0.23, 0.52, 0.25, 0.47, 0.51])
    assert bucket_sort([]) == [] and bucket_sort([1.0, 0.0]) == [0.0, 1.0]
    r = random.Random(1)
    data = [r.random() for _ in range(20_000)]
    assert bucket_sort(data) == sorted(data)
    temps = [r.uniform(-10, 40) for _ in range(2000)]
    assert bucket_sort(temps, -10, 40) == sorted(temps)
def test_spread():
    "bucket_sizes"
    r = random.Random(2)
    data = [r.random() for _ in range(10_000)]
    sizes = bucket_sizes(data)
    assert len(sizes) == 10_000 and sum(sizes) == 10_000 and max(sizes) <= 10
    assert bucket_sizes([0.0, 0.1, 0.99, 1.0]) == [2, 0, 0, 2]
    import re
    assert not re.search(r"\bsorted\(|\.sort\(", source)
@@hint
The bucket for `x` is `int((x - low) / (high - low) * n)`, capped at `n - 1` so that `x == high` lands in the last bucket.
@@solution
def bucket_index(x, low, high, n):
    i = int((x - low) / (high - low) * n)
    return min(i, n - 1)

def insertion(bucket):
    for i in range(1, len(bucket)):
        x, j = bucket[i], i - 1
        while j >= 0 and bucket[j] > x:
            bucket[j + 1] = bucket[j]
            j -= 1
        bucket[j + 1] = x

def bucket_sort(items, low=0.0, high=1.0):
    n = len(items)
    if n == 0:
        return []
    buckets = [[] for _ in range(n)]
    for x in items:
        buckets[bucket_index(x, low, high, n)].append(x)
    out = []
    for b in buckets:
        insertion(b)
        out.extend(b)
    return out

def bucket_sizes(items, low=0.0, high=1.0):
    n = len(items)
    sizes = [0] * n
    for x in items:
        sizes[bucket_index(x, low, high, n)] += 1
    return sizes
