## Warm-up

:::predict
x = 15
print(x > 10)
print(x < 12)
print(10 < x < 20)
print("a" < "B")
:::

The last one is `False`: capital `B` (66) comes before lower-case `a` (97). The chained comparison in the third line already combined two questions. Today you'll learn to combine any questions you like.

## and: both must be true

`and` puts two conditions together. The whole thing is `True` only when **both** sides are `True`.

:::example
age = 25
has_ticket = True
print(age >= 18 and has_ticket)
:::

A cinema lets you in only if you're old enough *and* you have a ticket. If either part fails, you're not getting in.

## or: at least one must be true

`or` is `True` when **at least one** side is `True`. It's only `False` when both sides are `False`.

:::example
day = "Sunday"
print(day == "Saturday" or day == "Sunday")
:::

:::note
In everyday English, "tea or coffee?" usually means one or the other, not both. Python's `or` is **inclusive**: if both sides are true, `or` is true too. "Is it raining or cold?" is true on a cold, rainy day.
:::

## not: flip it

`not` takes one condition and turns `True` into `False` and `False` into `True`.

:::example
is_raining = False
print(not is_raining)
print(not 5 > 3)
:::

## Truth tables

A **truth table** lists every combination of inputs and the answer for each. With two conditions there are only four combinations, so you can know the full behaviour of `and` and `or` by heart:

| `a` | `b` | `a and b` | `a or b` | `not a` |
|---|---|---|---|---|
| True | True | **True** | **True** | False |
| True | False | False | **True** | False |
| False | True | False | **True** | **True** |
| False | False | False | False | **True** |

Read the `and` column as "only the top row", and the `or` column as "all but the bottom row".

Now build your own. Type any condition using `a`, `b` and `c`, and the figure lists every combination:

:::widget truthtable caption="Every combination of True and False, and the value of your condition for each. Rows where it's True are green. Try the examples, then invent your own with c."
{"expr": "a and b"}
:::

:::predict
a = True
b = False
print(a and b)
print(a or b)
print(not a or b)
print(not (a or b))
:::

## Order of evaluation

When a condition mixes several operators, Python works in this order:

1. Arithmetic (`*`, `+` and the rest)
2. Comparisons (`==`, `<`, `in` and the rest)
3. `not`
4. `and`
5. `or`

So `not` binds tightest of the three, and `or` happens last. Step through this one:

:::stepper caption="Arithmetic, then comparisons, then not, then and, then or."
x + 1 > 5 and not x == 9 or x == 0
@@vars
{"x": 7}
:::

`a or b and c` means `a or (b and c)`, because `and` goes first. If you have to stop and think about the order, so will anyone reading your code. Add brackets:

:::example
x = 7
print(x > 5 and x < 10 or x == 100)
print((x > 5 and x < 10) or x == 100)
:::

Both lines mean the same thing, but the second says so out loud.

:::tip
Brackets cost nothing and remove all doubt. Use them whenever a condition mixes `and` with `or`.
:::

## The classic mistake: x == 1 or 2

You want to know whether `x` is 1 or 2. In English you'd say "is x equal to 1 or 2?", so it's tempting to write this:

:::example title="Looks right. Isn't."
x = 7
print(x == 1 or 2)
:::

It prints `2`, not `False`. Python reads it as `(x == 1) or (2)`: the left side is `False`, so the answer is whatever the right side is, and the right side is just the number 2. Worse, `2` is truthy, so when you use this condition to make a decision next lesson, it will **always** count as true, whatever `x` is.

:::stepper caption="The or doesn't share the x == part. Each side stands alone."
x == 1 or 2
@@vars
{"x": 7}
:::

The fix is to write each comparison in full:

:::example
x = 7
print(x == 1 or x == 2)
:::

:::key
Each side of `and` and `or` is a complete condition on its own. `x == 1 or 2` is not "x is 1 or 2"; write `x == 1 or x == 2`.
:::

## Short-circuit evaluation

Python is lazy in a useful way. It works from left to right and stops as soon as it knows the answer:

- `False and anything` is always `False`, so Python never looks at `anything`.
- `True or anything` is always `True`, so again Python skips the right side.

This is called **short-circuit evaluation**. You can see it happen. In both lines below, the right side would crash if Python ever ran it:

:::example
print(False and 1 / 0 > 1)
print(True or 1 / 0 > 1)
:::

No `ZeroDivisionError`, because the division never runs. Swap the sides and it does:

:::example error=yes
print(1 / 0 > 1 and False)
:::

This isn't just a curiosity. It lets you write a **guard**: a check on the left that protects the code on the right.

:::example title="A guard" try=0
count = int(input("Number of items: "))
total = 120
print("Big average:", count != 0 and total / count > 50)
:::

Run it with `0`. If `count` is 0, `count != 0` is `False`, and Python never attempts the division. Run it again with `2`. Press X-ray in both cases and watch what Python evaluates.

:::think
In `count != 0 and total / count > 50`, would swapping the two sides around still be safe? Why does the order of a guard matter?
:::

## and and or return one of their sides

So far `and` and `or` have given `True` or `False`, because both sides were bools. Strictly, they give back **one of the two values**:

- `a or b` gives `a` if `a` is truthy, otherwise `b`.
- `a and b` gives `a` if `a` is falsy, otherwise `b`.

That explains why `x == 1 or 2` printed `2`. It also gives a neat way to supply a **default** when the user types nothing:

:::example title="Press Enter without typing" try=""
name = input("Name: ") or "friend"
print(f"Hello, {name}!")
:::

If the user types nothing, `input()` returns `""`, which is falsy, so `or` gives back `"friend"`.

:::predict
print("" or "default")
print("Ada" or "default")
print(0 or 5)
print(3 and 4)
print(0 and 4)
:::

## De Morgan's laws

Sometimes you need the opposite of a combined condition. Augustus De Morgan, another nineteenth-century mathematician, noticed two rules:

- `not (a and b)` is the same as `not a or not b`
- `not (a or b)` is the same as `not a and not b`

In words: when you push a `not` inside brackets, it flips each part, and `and` and `or` swap places. Check it yourself. The figure compares two conditions row by row:

:::widget truthtable caption="The left column is your condition; the right is not a or not b. If every row matches, the two are the same condition. Change the left one to not (a or b) and see them disagree."
{"expr": "not (a and b)", "compare": "not a or not b", "tries": ["not (a and b)", "not (a or b)", "not a and not b"]}
:::

An everyday example: "not (rainy and cold)" means "not rainy, or not cold": at least one of the two is fine.

:::example title="Two ways to say 'outside the range'"
t = 30
print(not (18 <= t <= 24))
print(t < 18 or t > 24)
:::

Both are correct. The second, with no `not`, is usually easier to read.

## Readable conditions

Long conditions are hard to check. Give the parts names:

:::example title="Hard to read"
age, has_id, with_adult = 15, False, True
print((age >= 18 and has_id) or (age >= 12 and with_adult))
:::

:::example title="Easier"
age, has_id, with_adult = 15, False, True
adult_with_id = age >= 18 and has_id
older_child_with_adult = age >= 12 and with_adult
print(adult_with_id or older_child_with_adult)
:::

Same answer, but each line can be checked on its own, and the last line reads like the rule it implements.

## Quiz

:::quiz id=quiz
- q: When is `a and b` True?
  options: ["When either is True", "Only when both are True", "When exactly one is True", "When both are False"]
  answer: 1
  explain: "and needs both sides."
- q: When is `a or b` False?
  options: ["When either is False", "Only when both are False", "When both are True", "Never"]
  answer: 1
  explain: "or is True if at least one side is."

    print(not True or True)

  code: |
    print(True or False and False)
  answer: "True"

  type: output
  code: |
    x = 3
    print(x == 1 or 2)
  answer: "2"
  explain: "(x == 1) is False, so or gives back the right side: 2."
- q: Which line could crash with a ZeroDivisionError when d is 0?
  options: ["`d != 0 and 10 / d > 1`", "`10 / d > 1 and d != 0`", "`d == 0 or 10 / d > 1`"]
  answer: 1
  explain: "In the others, the guard on the left stops Python before the division."
- q: Which is the same as `not (a or b)`?
  options: ["`not a or not b`", "`not a and not b`", "`a and b`", "`not a and b`"]

  explain: "De Morgan: push not inside, and or becomes and."

  type: output

    n = 15
    print(n % 3 == 0 and n % 5 == 0)
  answer: "True"
  explain: "15 divides by both."
- q: Which is the clearest way to write "x is not between 1 and 10"?
  options: ["`not 1 <= x <= 10`", "`x < 1 or x > 10`", "`x < 1 and x > 10`"]
  answer: 1
  explain: "The first is correct but needs a moment's thought; the third is never True."
