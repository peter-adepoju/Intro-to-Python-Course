## Warm-up

:::predict
x = 12
if x > 10:
    print("A")
else:
    print("B")
if x > 20:
    print("C")
print("D")
:::

Two separate decisions, so Python checks both. Today you'll learn to join decisions into one chain where only one answer can win.

## More than two choices: elif

Suppose a mark of 70 or more is an A, 60 or more a B, 50 or more a C, and anything lower an F. With only `if` and `else` you could nest them, but Python has a neater way, `elif` (short for "else if"):

:::example title="Grades" try=64
mark = int(input("Mark: "))
if mark >= 70:
    grade = "A"
elif mark >= 60:
    grade = "B"
elif mark >= 50:
    grade = "C"
else:
    grade = "F"
print("Grade:", grade)
:::

How Python runs a chain:

1. Check the `if` condition. If it's true, run its block and **skip the rest of the chain**.
2. Otherwise check the first `elif`. If it's true, run its block and skip the rest.
3. And so on down the chain.
4. If nothing was true, run the `else` block.

So **exactly one** block runs, and it's the **first** one whose condition is true. Move the slider and watch Python work down the chain:

:::widget branch caption="Python checks each condition from the top and stops at the first True one. Conditions below it are never checked, even if they would also be True. The strip shows which grade every mark gets."
{"name": "mark", "value": 64, "min": 0, "max": 100, "branches": [["mark >= 70", "grade = 'A'"], ["mark >= 60", "grade = 'B'"], ["mark >= 50", "grade = 'C'"], [null, "grade = 'F'"]]}
:::

With 64, `mark >= 60` is true, so the grade is B. `mark >= 50` is also true, but Python never even looks at it.

:::note
The `else` at the end is optional. Without it, if no condition is true, no block runs at all.
:::

## The order matters

Because the first true condition wins, the order of the conditions is part of the logic. Here is the same chain with the order mixed up:

:::widget branch caption="The same four conditions in a different order. Try marks of 95 and 65. Every passing mark lands in the first branch."
{"name": "mark", "value": 95, "min": 0, "max": 100, "branches": [["mark >= 50", "grade = 'C'"], ["mark >= 60", "grade = 'B'"], ["mark >= 70", "grade = 'A'"], [null, "grade = 'F'"]]}
:::

Everyone with 50 or more gets a C, because `mark >= 50` is checked first and is true for all of them. The B and A branches can never run. Python doesn't warn you: the code is legal, just wrong.

:::key
In an `elif` chain with `>=`, put the **largest** threshold first. With `<`, put the **smallest** first. Then each test only has to rule out what the earlier ones haven't.
:::

:::predict
t = 28
if t < 10:
    print("cold")
elif t < 20:
    print("mild")
elif t < 30:
    print("warm")
else:
    print("hot")
:::

## elif or separate ifs?

An `elif` chain picks **one** branch. Separate `if` statements are separate questions: each is checked, and any number of them can run.

:::widget branch caption="The same conditions as separate ifs. Now every true condition runs its block. Try a mark of 75."
{"name": "mark", "value": 75, "min": 0, "max": 100, "branches": [["mark >= 70", "print('A')"], ["mark >= 60", "print('B')"], ["mark >= 50", "print('C')"]], "chain": false, "strip": false}
:::

With 75, all three blocks run and the program prints A, B and C. That's wrong for grades, which are one answer. But separate `if`s are right when the questions are independent:

:::example title="Independent checks, so separate ifs" try=hello
password = input("Password: ")
if len(password) < 8:
    print("Too short")
if password == password.lower():
    print("Needs a capital letter")
if password.isalpha():
    print("Needs a digit or symbol")
:::

(`.isalpha()` is `True` when every character is a letter. More methods like it in Week 5.) A weak password can fail all three tests, and the user should hear about all of them.

:::tip
Ask: "Can more than one of these be true and *should* they all happen?" If yes, separate `if`s. If only one answer makes sense, an `elif` chain.
:::

## Decisions inside decisions

A block can hold any statements, including another `if`. This is a **nested** decision:

:::example title="Nested" try=y,25
member = input("Member? (y/n) ") == "y"
age = int(input("Age: "))
if member:
    if age < 18:
        print("Junior member: free")
    else:
        print("Member: 500")
else:
    print("Visitor: 1500")
:::

The inner `if` is indented one more level (8 spaces). It only gets checked when `member` is true. Press X-ray and step through with a few different answers: you can see Python go down into the outer block before it even looks at the age.

:::predict
a = 5
b = 3
if a > 4:
    if b > 4:
        print("both")
    else:
        print("only a")
else:
    print("not a")
:::

### The largest of three

A classic. One way is to nest:

:::example
a, b, c = 4, 9, 7
if a >= b:
    if a >= c:
        largest = a
    else:
        largest = c
else:
    if b >= c:
        largest = b
    else:
        largest = c
print(largest)
:::

Another is an `elif` chain with `and`:

:::example
a, b, c = 4, 9, 7
if a >= b and a >= c:
    largest = a
elif b >= c:
    largest = b
else:
    largest = c
print(largest)
:::

The second is shorter. It also uses a fact the chain gives you for free: when Python reaches `elif b >= c`, it already knows `a` isn't the largest.

## Flattening

Deep nesting is hard to read, because you have to keep every outer condition in your head. Often `and` lets you flatten it:

:::example title="Nested"
age, has_licence = 20, True
if age >= 18:
    if has_licence:
        print("You may drive")
:::

:::example title="Flat, same meaning"
age, has_licence = 20, True
if age >= 18 and has_licence:
    print("You may drive")
:::

Nesting is the better choice when the outer branch has its own work to do, or its own `else`, as in the member example above. If the outer `if` exists only to hold the inner one, flatten it.

    print("Player 2 wins")

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: days in a month"
Ask for a month number (1 to 12) with the prompt `Month: ` and a year with the prompt `Year: `, and print `Days: ` and the number of days in that month.

- April, June, September and November (4, 6, 9, 11) have 30 days.
- February has 29 days in a leap year and 28 otherwise (use the leap-year rule from yesterday).
- All the others have 31.

@@starter

@@tests

    "February in different years"
    expect_output("Month: 2\nYear: 2023\nDays: 28", inputs=["2", "2023"], echo=True)
    expect_output("Month: 2\nYear: 2024\nDays: 29", inputs=["2", "2024"], echo=True)
    expect_output("Month: 2\nYear: 1900\nDays: 28", inputs=["2", "1900"], echo=True)
    expect_output("Month: 2\nYear: 2000\nDays: 29", inputs=["2", "2000"], echo=True)

    "month 13"
    expect_output("Month: 13\nYear: 2023\nNo such month", inputs=["13", "2023"], echo=True)
@@hint
Check for an impossible month first. Then February, then the four 30-day months, then `else` for 31.
@@hint
Inside the February branch, nest an `if` (or a conditional expression) on the leap-year condition.
@@solution
month = int(input("Month: "))
year = int(input("Year: "))
if month < 1 or month > 12:
    print("No such month")
else:
    if month == 2:
        leap = (year % 4 == 0 and year % 100 != 0) or year % 400 == 0
        days = 29 if leap else 28
    elif month == 4 or month == 6 or month == 9 or month == 11:
        days = 30
    else:
        days = 31
    print("Days:", days)
:::
