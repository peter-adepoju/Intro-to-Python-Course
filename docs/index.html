How every day works

  
    
    
  1. Warm up. A few predictions about yesterday's code, plus your review cards. Ten minutes that make yesterday stick.
    2. 
    
  2. See it. Every idea comes with a live figure: memory, objects and the yellow pointer moving through real Python as it runs.
    3. 
    
  3. Predict it. Before running code, you write down what you think it prints. The gap between guess and result is where learning happens.
    4. 
    
  4. Write it. Ten to fifteen exercises, bug hunts and puzzles, checked instantly by hidden tests that tell you exactly what's wrong.
    5. 
    
  5. Prove it. A short quiz and a daily challenge. Questions you miss come back in your review, spaced out until they stick.
    6. 
  

  
Six days a week. Day six is a Forge: a bigger build, a weekly quiz and a review. Day seven is rest. Every phase ends with a project, an exam and a rest week.
