Forge: the password rule kit

About an hour. Websites have password rules, and they keep changing them. Instead of one long function full of ifs, you’ll make each rule a function, and build a checker that applies any rules it’s given.

A rule is a function that takes a password and returns an empty string if the password is fine, or a short message saying what’s wrong.

Exercise50 points
Forge: the password rule kit

Write these, each with a docstring:

  1. min_length(n) returns a rule that complains At least N characters (with the number) when the password is shorter than n.
  2. needs(test, what) returns a rule that complains Needs WHAT when no character of the password passes test. For example needs(str.isdigit, "a digit") complains Needs a digit.
  3. no_spaces(password) is itself a rule: it complains No spaces allowed when the password contains a space.
  4. check(password, *rules) applies every rule in order and returns all the complaints joined with "; ", or "OK" if there are none.
  5. test_check() tests check with at least four asserts, including one that expects "OK" and one that expects two complaints at once.

Finally, the main program builds this rule set and checks the password typed after the prompt Password::

rules = (min_length(8), needs(str.isupper, "a capital letter"), needs(str.isdigit, "a digit"), no_spaces)

Password: hello world
Needs a capital letter; Needs a digit; No spaces allowed

(hello world has 11 characters, so the length rule is happy.) Use check(password, *rules) to pass the rules in.

Why rules as functions?

Suppose the website adds a rule tomorrow: “needs a symbol”. With one big function, you’d edit its middle and hope nothing else breaks. With rules as functions, you write needs(lambda c: not c.isalnum(), "a symbol") and add it to the tuple. Nothing else changes, and test_check still guards the checker. This idea of building behaviour out of small interchangeable functions is used all over professional software.

Forge bonus: encode, decode, round trip

Exercise30 points
Forge bonus: round trip

In Week 4 you wrote run-length encoding: aaabcc becomes a3b1c2. Now write both directions, and test them against each other.

  1. encode(text) returns the run-length encoding. Text may contain any characters except digits.
  2. decode(code) turns an encoding back into the text. A count may have several digits: x12 means twelve xs.
  3. test_round_trip() checks that decode(encode(s)) == s for at least six different strings, including the empty string, a single character, and a run longer than 9.

A round-trip test checks two functions that undo each other at the same time: if either is wrong, the round trip almost always fails.
