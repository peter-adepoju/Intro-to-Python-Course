Forge: a library catalogue

A small community library keeps its books as records (title, author, year, loans), where loans is how many times the book has been borrowed. Here is a sample:

BOOKS = [
    ("Things Fall Apart", "Chinua Achebe", 1958, 41),
    ("Half of a Yellow Sun", "Chimamanda Ngozi Adichie", 2006, 37),
    ("The Famished Road", "Ben Okri", 1991, 22),
    ("Purple Hibiscus", "Chimamanda Ngozi Adichie", 2003, 41),
    ("Arrow of God", "Chinua Achebe", 1964, 15),
    ("The Joys of Motherhood", "Buchi Emecheta", 1979, 22),
    ("Stay With Me", "Ayobami Adebayo", 2017, 30),
    ("The Fishermen", "Chigozie Obioma", 2015, 30),
    ("Americanah", "Chimamanda Ngozi Adichie", 2013, 52),
    ("No Longer at Ease", "Chinua Achebe", 1960, 15),
]
Exercise50 points
Forge: a library catalogue

Write these functions. Don’t use sort, sorted, min, max or bisect anywhere: you’re building them yourself.

  1. stable_sort(records, key): return a new list sorted by key(record), stable, using insertion sort.
  2. catalogue(books): the books sorted by author (the whole name as written, A to Z), then by year (oldest first), using two calls to stable_sort.
  3. title_index(books): the books sorted by title, ignoring capitals.
  4. find_title(index, title): binary search a title_index list for a title (ignoring capitals); return the record or None.
  5. starting_with(index, prefix): every record in a title_index list whose title starts with prefix (ignoring capitals), in index order. Use binary search to find the first title that is not less than the prefix, then go forward while titles still start with it, so the cost is O(log n + number found).
  6. most_borrowed(books, k): the k books with the most loans, highest first; ties go to the book that comes first in books. Use k rounds of a selection that picks the largest, on a copy (O(kn)), making sure ties are broken by original position.
Choosing the right tool each time

Look at which algorithm each function used. A one-off sort of a small list: insertion sort is fine. Many title lookups: sort once, then O(log n) binary search each time. All titles with a prefix: binary search to the start, then a short walk. Just the top few: k rounds of selection instead of a whole sort. In real code you’d use sorted, bisect and heapq.nlargest, but the reasons for choosing each are exactly the ones you’ve just used.

Forge bonus: searching a rotated list

A sorted list has been rotated: some number of items were moved from the front to the end, so [1, 3, 5, 7, 9, 11] might now be [7, 9, 11, 1, 3, 5]. It’s no longer sorted, so ordinary binary search fails, and a linear search is O(n). But it’s made of two sorted pieces, and that’s enough for an O(log n) search.

The key fact: if you cut the part you’re searching in the middle, at least one half is properly sorted. You can tell which by comparing its ends, and for a sorted half you can tell at once whether the target lies inside it.

Exercise30 points
Forge bonus: searching a rotated list

The list holds different numbers. Write:

  • find_rotation(items): the position of the smallest item (the number of places it was rotated), in O(log n). Compare the middle with the last item: if items[mid] > items[hi], the smallest is to the right of mid; otherwise it’s at mid or to its left.
  • rotated_search(items, target): the position of target or -1, in O(log n), with a single binary search: at each step decide which half is sorted (items[lo] <= items[mid] means the left half is), check whether the target is inside the sorted half’s range, and keep that half or the other.

Both must handle a list that wasn’t rotated at all, a single item and an empty list (find_rotation([]) is 0).
