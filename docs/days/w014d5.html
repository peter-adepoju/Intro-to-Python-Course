Week 14, Day 5

Your pattern library

Experienced programmers rarely invent a solution from nothing. They recognise the shape of a problem, “this is a running total”, “this needs a seen-set”, “this is a sliding window”, and reach for a pattern they’ve used many times. Today you’ll gather the patterns you already know into one library, add three powerful new ones (two pointers, sliding windows and prefix sums), and practise choosing the right one.

By the end of today you can

  • Name the common loop patterns and write each from memory
  • Recognise which pattern a problem needs from how it’s described
  • Use two pointers on a sequence from both ends
  • Use a sliding window to examine every run of k neighbouring items efficiently
  • Use prefix sums to answer many range-total questions quickly

Warm-up

For each of these, which loop would you write, without writing it?

  1. Is any mark below 40?
  2. The total of all the prices.
  3. The words that appear more than once.
  4. The position of the first negative number.
  5. The longest word.

You probably “saw” the answer to each one before thinking about the details: a check that stops early, a running total, a seen-set, a search that stops at the first match, a best-so-far. Those are patterns, and naming them makes them easier to reach for.

Key idea

When you meet a problem, ask: which words in it match a pattern? “How many of each” is a frequency map. “Is there any” is any. Most problems are two or three patterns combined.

Two pointers

Some problems on a sequence are easiest with two positions moving towards each other from the ends. The classic is checking a palindrome without making a reversed copy:

The real power shows on sorted lists. To find two numbers in a sorted list that add up to a target: start at both ends. If the sum is too small, the only way to make it bigger is to move the left pointer right; if it’s too big, move the right one left.

Each step moves one pointer, so the whole list is examined in one pass, instead of trying every pair. (You’ll measure how much that matters in Week 17.)

Sliding windows

Many problems ask about every run of k neighbouring items: the best 3-day total, the busiest hour, the longest stretch without a repeat. The slow way adds up each window from scratch. The sliding window way keeps the current window’s total and updates it as the window slides: add the item coming in, subtract the item going out.

Windows can also stretch and shrink: to find the longest run of different characters, grow the window on the right, and shrink it from the left whenever a repeat gets in. You’ll do that in the daily challenge.

Prefix sums

Suppose you’ll be asked many questions like “what’s the total from position 3 to position 7?”. Adding up each range is slow if there are many questions. Instead, work out once the running totals, where prefix[i] is the sum of the first i items. Then any range total is one subtraction:

prefix has one more item than values, starting with 0, so that the empty range and the range from the start need no special cases.

Choosing a pattern

The problem mentions… Try
each item compared with the next neighbours
a pair, in a sorted list, or the two ends two pointers
every run of k neighbouring items, or the longest stretch with some property sliding window
many questions about totals of ranges prefix sums
matching, nesting, “most recent” stack
“have I seen this before?” seen-set
“how many of each?” frequency map

Exercise10 points
A sentence palindrome

Moving averages

Write moving_averages(values, k) that returns the average of every window of k neighbouring values, each rounded to 2 places, using a sliding window (a running total, not sum of each window). Raise a ValueError if k isn’t from 1 to len(values).

Rainfall questions

Two patterns at once

In "to be or not to be" the pair ("to", "be") appears at the start and again at the end, so it’s the answer. It combines two patterns: name them before you start.

Challenge: the longest run without repeats
