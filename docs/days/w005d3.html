Week 5, Day 3

Walking through text

Real text is messy: punctuation, capitals, numbers mixed in with words, lines of different lengths. Today you’ll learn the techniques for scanning text properly: looking at a window of characters at a time, searching for a pattern yourself, reading text line by line, counting how often every letter appears, and checking that text has the right format.

By the end of today you can

  • Compare a slice with a pattern to find every occurrence of a substring, including overlapping ones
  • Walk through text with a sliding window of a fixed width
  • Work with multi-line text using \n and .splitlines()
  • Count how often each letter appears, and use the counts to compare words
  • Check that a string has an exact format, such as a time or a code

This simple method can be slow for long patterns with many near misses: for every position it might compare almost the whole pattern. Python’s own find uses cleverer algorithms. You’ll study them in Phase 4.

Sliding windows

The search above looks at a window of the text, len(pattern) characters wide, at every position. The window idea is useful on its own:

Every three-letter chunk
The pair of digits with the biggest sum

Windows are how spell checkers suggest corrections, how DNA sequences are searched, and how you spot the hottest week in a year of temperature readings.

Line by line

Text often has several lines. Inside a string, a line break is the single character \n. A string written with three quotes can span lines directly:

.splitlines() splits at every line break and returns the lines without the \n characters. Each line is an ordinary string: you can split it into words, strip it, search it.

Anagrams

Two words are anagrams if they use exactly the same letters the same number of times: listen and silent. With letter counts, the check is simple: the words are anagrams when every letter has the same count in both.

Checking a format

Many strings must follow a fixed format: a time like 14:05, a postcode, a product code. Checking one means checking its length, then each part:

Is it a valid 24-hour time?

Notice the brackets around the long condition: inside brackets, Python lets you continue on the next line. And notice the order: the length is checked first, so the slices are safe, and .isdigit() is checked before int(), so it can’t crash. Short-circuit evaluation from Week 2 is doing real work here.

Tip

Check a format from the outside in: the length first, then the fixed characters (like :), then each part’s kind, and only then its value.
