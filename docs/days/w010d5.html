Phase 1: Foundations Week 10, Day 5

Sets

A set is a collection with no order and no duplicates: like a dictionary with keys but no values. That makes it the perfect tool for two jobs: asking whether something is in a collection, very quickly, and comparing collections, such as finding the students who take both maths and physics. Today you’ll learn both.

By the end of today you can

  • Make sets, including the empty set, and remove duplicates with set
  • Add and remove elements, and check membership with in
  • Combine sets with union, intersection, difference and symmetric difference
  • Test whether one set is a subset of another, or the two have nothing in common
  • Choose between a list, a set and a dictionary, and explain why in is fast for a set

The empty set

{} is an empty dictionary. An empty set has to be written set():

What can be in a set

Elements follow the same rule as dictionary keys: they must be hashable (strings, numbers, tuples, not lists or dictionaries). That isn’t a coincidence. A set works like a dictionary’s keys: Python stores each element at a place worked out from its hash, so checking whether something is there doesn’t need a search.

Key idea

A set holds unique, hashable elements in no particular order. x in s takes about the same time whatever the size of the set. Use a set when you care whether something is there, not where or how many times.

Set operations

The real power of sets is combining them. Suppose a and b are the students taking two subjects:

  • a | b, the union: students in either (or both);
  • a & b, the intersection: students in both;
  • a - b, the difference: in a but not in b;
  • a ^ b, the symmetric difference: in exactly one of them.

Each operator makes a new set. There are method versions too, a.union(b), a.intersection(b), a.difference(b) and a.symmetric_difference(b), which accept any sequence, not just a set:

And there are versions that change a set in place: a |= b, a &= b, a -= b.

Two sets are equal when they hold the same elements, whatever order you wrote them in:

Choosing a collection

You now know the four built-in collections. Choose by what you need to do:

Collection Ordered? Duplicates? Changeable? Use it for
list [...] yes yes yes a sequence of things, in order
tuple (...) yes yes no a fixed group of values, a record, a key
dict {k: v} by insertion keys unique yes looking up a value by a key
set {...} no no yes membership, removing duplicates, comparing groups

Speed matters too. Here’s the difference for in:

The exact times depend on your computer, but the set is usually hundreds of times faster, and the gap grows with the size. You’ll learn to measure and reason about this properly in Phase 2.

Common mistake

Don’t use a list for frequent “is it in here?” checks on large data, and don’t use a set when the order or the count matters. Turning a list into a set throws away both.
