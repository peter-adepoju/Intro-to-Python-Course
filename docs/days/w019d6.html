Forge: a smart sort

No single sort is best for every input. A tiny list is fastest with insertion sort. Whole numbers in a small range can be counted. Data that’s already mostly in order can be merged run by run. Everything else wants a good general sort. Real libraries make choices like these all the time.

Exercise50 points
Forge: a smart sort

Write each algorithm as a function that takes a list and returns a new sorted list (the input unchanged), none of them using sort or sorted:

  1. insertion_sort(items)
  2. merge_sort(items): stable, top-down.
  3. quick_sort(items): random pivot, three-way partition (so repeated values are fast). It may use list comprehensions or work in place on a copy.
  4. counting_sort(items): whole numbers only, any sign (shift by the smallest).
  5. run_count(items): how many non-decreasing runs the list has (0 for an empty list).

Then smart_sort(items) returns (sorted_list, name), choosing in this order:

  • fewer than 20 items: "insertion";
  • all items are whole numbers (type(x) is int) and max - min is at most 2 * len(items): "counting";
  • at most len(items) // 50 + 1 runs (the data is mostly in order): "merge" (merge sort is fine here; a real library would merge the runs directly);
  • otherwise: "quick".
Cheap checks, big savings

Each check in smart_sort costs one pass over the data, O(n), and can save far more: counting instead of comparing, or a handful of merges instead of a full sort. Timsort’s run detection is the same idea built into the sort itself. Whenever data might have structure (a small range, existing order, many repeats), a quick look before choosing an algorithm often pays for itself many times over.

Forge bonus: bucket sort

Counting sort needs whole numbers in a small range. Bucket sort handles decimal numbers spread fairly evenly over a known range, such as random numbers from 0 to 1. Make n buckets, each covering an equal slice of the range; drop each number into its bucket; sort each bucket (they’re small, so insertion sort is ideal); and join the buckets in order.

If the numbers are spread evenly, each bucket gets about one number, and the whole sort is O(n) on average. If they all land in one bucket, it’s as slow as insertion sort on everything: O(n²).

Exercise30 points
Forge bonus: bucket sort

Write bucket_sort(items, low=0.0, high=1.0) that sorts numbers in the range low <= x < high (the value high itself may also appear and goes in the last bucket) using len(items) buckets and insertion sort inside each bucket. Also write bucket_sizes(items, low=0.0, high=1.0) that returns the list of how many items fell in each bucket, so you can see how evenly they spread. Don’t use sort or sorted.
