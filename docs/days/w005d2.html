Week 5, Day 2

split, join, immutability

Most text is made of pieces: words in a sentence, values in a line, parts of a date. split breaks a string into its pieces and join glues pieces back together. Today you’ll use them to read several values from one line, rearrange words, and reformat data, and you’ll see why strings can never be changed in place.

By the end of today you can

  • Break a string into a list of pieces with split() and split(sep), and know how they differ
  • Loop over, index and count the pieces
  • Join pieces back together with sep.join(pieces)
  • Read several numbers typed on one line
  • Explain why strings are immutable, and what to do instead of changing one

Warm-up

Last week, counting words took a loop, a flag and some care. Today it takes one method call.

split: one string into many

.split() cuts the string wherever there’s whitespace and gives back the pieces. The result, written with square brackets, is a list: an ordered collection of values. Lists get two whole weeks of their own (Weeks 8 and 9). For now you only need three things, and they all work the way they do for strings:

  • len(words) is how many pieces there are;
  • words[0] is the first piece, words[-1] the last;
  • for w in words: visits each piece in turn.

Key idea

split() with no argument is for words: runs of whitespace count as one break. split(sep) is for data with a fixed separator: every single separator makes a break, even if that gives empty pieces.

join is the opposite of split. You call it on the separator, and pass it the pieces:

It reads a little backwards at first: "-".join(words) means “join the words, with - between them”. The separator goes between pieces, never at the start or end, so there’s no trailing comma to remove.

Common mistake

join only joins strings. Joining numbers raises a TypeError. Convert them first, with str().

Strings can’t be changed

You’ve seen hints of this all week. Now the rule: once a string exists, it can never be changed. Not one character of it.

TypeError: 'str' object does not support item assignment. To get "hello", you build a new string and point the name at it:

This is called immutability, and it’s deliberate. Remember from Week 1 that names are labels on objects. If two names point at the same string and strings could change, changing it through one name would silently change it for the other. Because strings are immutable, sharing them is always safe:

Sharing is safe

a.upper() made a new string, and a = ... moved the label a to it. b still points at the original. In Week 8 you’ll meet lists, which can change, and this exact situation becomes a famous source of bugs.

Note

Building a long string one piece at a time with += creates a new string every time. For a few hundred pieces it doesn’t matter. For millions, collect the pieces and join them once; you’ll see how in Week 8.

Exercise25 points
Challenge: Pig Latin

Pig Latin is a word game. To translate a word:

  • if it starts with a vowel (a, e, i, o, u), add way to the end: apple → appleway;
  • otherwise, move all the consonants before the first vowel to the end and add ay: string → ingstray, pig → igpay;
  • a word with no vowels at all just gets ay: rhythm → rhythmay.

Ask for a sentence (lower-case words, no punctuation) with the prompt Sentence: and print it in Pig Latin, words separated by single spaces.
