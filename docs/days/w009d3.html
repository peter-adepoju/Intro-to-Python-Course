Week 9, Day 3

Tuples and unpacking

A tuple is a list that can’t be changed. That sounds like a weaker list, but it’s exactly right for fixed groups of values like a point’s coordinates, a date, or the several results of a function. Today you’ll meet tuples properly, and master unpacking: pulling the values out of any sequence into names in one line.

By the end of today you can

  • Write tuples, including the one-item tuple, and index and slice them
  • Explain why a tuple can’t be changed, and when to choose a tuple over a list
  • Unpack any sequence into names, including in for loops and with a starred name
  • Return several values from a function and unpack them
  • Compare tuples, and use them as sort keys and as fixed records

Careful

A tuple’s slots can’t be pointed elsewhere, but if one of its items is a list, that list can still be changed. t = ([1], [2]) then t[0].append(5) works: the tuple still holds the same two lists; one of them just has more in it.

Tuples or lists?

Both hold sequences. Choose by what the data is:

Use a tuple when… Use a list when…
the group has a fixed size and meaning: (x, y), (year, month, day), (name, score) you’ll add or remove items
the values shouldn’t change items are all the same kind of thing, in any number
you’re returning several values from a function you’ll sort it in place, or change items

A good rule of thumb: a list is like a column in a table (many values of the same kind), and a tuple is like a row (one record, with a fixed meaning for each position).

Immutability is also a guarantee. If you give a tuple to a function, you know for certain it comes back unchanged: none of last week’s aliasing surprises can happen. And in Week 10 you’ll see that tuples can be used as dictionary keys, which lists can’t.
