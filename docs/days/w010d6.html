Forge: the library

Exercise50 points
Forge: the library

Build the core of a library system. The whole library is one dictionary:

library = {
    "books": {},    # isbn -> {"title": ..., "author": ..., "copies": ...}
    "loans": {},    # member name -> set of isbns they have borrowed
}

A member may have at most 3 books at once, and never two copies of the same book. A book’s available copies are its copies minus the number of members who have borrowed it. Write:

  • new_library() returns an empty library like the one above.
  • add_book(library, isbn, title, author, copies) adds a book, or adds copies more to a book that’s already there.
  • borrow(library, member, isbn) returns one of these messages, changing the library only for OK, checked in this order: No such book, Already borrowed, Limit reached, None available, OK.
  • give_back(library, member, isbn) returns OK (and records the return) or Not borrowed. A member with nothing left on loan is removed from loans.
  • available(library, isbn) returns the number of copies on the shelf.
  • report(library) returns one line per book, sorted by title: Title by Author: 1 of 2 available, joined with "\n".
  • process(library, command) carries out one command and returns its message: borrow NAME ISBN, return NAME ISBN, report, or who ISBN, which returns the borrowers’ names sorted and joined with ", ", or nobody. Anything else returns Unknown command. Member names are one word.
  • The main program makes a library, adds the two books below, then reads commands with the prompt > until quit, printing each message.
add_book(lib, "111", "Things Fall Apart", "Chinua Achebe", 2)
add_book(lib, "222", "Americanah", "Chimamanda Ngozi Adichie", 1)

For example:

> borrow Ada 222
OK
> borrow Bo 222
None available
> who 222
Ada
> report
Americanah by Chimamanda Ngozi Adichie: 0 of 1 available
Things Fall Apart by Chinua Achebe: 2 of 2 available
> quit
One fact, one place

Notice that the library never stores how many copies are available. It works that out from copies and loans whenever it’s asked. If it stored the number as well, every borrow and return would have to update two things, and one day a bug would update only one of them. Storing each fact in exactly one place, and working everything else out from it, is one of the most useful rules in data design. Real databases are built around it.

Forge bonus: a spelling corrector

This bonus is based on a famous short essay by Peter Norvig, “How to Write a Spelling Corrector”. The idea: most typing mistakes are one small edit away from the word that was meant, and among the real words one edit away, the most likely is the most common one.

Exercise30 points
Forge bonus: a spelling corrector

An edit of a word is one of:

  • a delete: remove one letter ("speling" → "seling");
  • a swap: swap two neighbouring letters ("teh" → "the");
  • a replace: change one letter to another letter a to z;
  • an insert: add one letter a to z anywhere, including at the ends.

Write:

  1. edits(word) returns the set of every word one edit away (the word itself may be included, through a replace with the same letter, which is fine).
  2. train(text) returns a Counter of the words in the text, in lower case, counting only runs of letters (treat every non-letter as a space).
  3. correct(word, counts) returns, in lower case: the word itself if it’s known (in counts); otherwise the most common known word one edit away; otherwise the word unchanged. If known words tie, return the alphabetically first.

Use comprehensions to build the edits. The split points are [(word[:i], word[i:]) for i in range(len(word) + 1)].

Train it on a whole book and it corrects most single typos. Norvig’s full version also looks two edits away, and you could add that now: the edits of every edit.
