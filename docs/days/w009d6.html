Forge: the league table

In most football leagues a win earns 3 points, a draw 1 and a loss 0. Teams are ranked by points; teams level on points are separated by goal difference (goals scored minus goals conceded), then by goals scored. Today you’ll build the table from the raw results.

Exercise50 points
Forge: the league table

Each result is a line like Red Stars 2-1 Blue Union: the home team, the score, the away team. Team names may contain spaces. Write:

  • parse_result(line) returns a tuple (home, home_goals, away_goals, away), with the names stripped and the goals as ints. The score is the only word made of digits, a -, and digits.
  • league(results) takes a list of such tuples and returns the table as a list of tuples (team, played, won, drawn, lost, goals_for, goals_against, points), sorted by points, then goal difference, then goals for (all highest first), then team name (A to Z).
  • format_table(rows) returns the table as one string, lines joined with "\n": a header, then one line per team. Pos is right-aligned in 3, then a space, the team left-aligned as wide as the longest name or Team, then P, W, D, L each right-aligned in 3, GF, GA, GD and Pts each right-aligned in 4. The goal difference always shows its sign, as in +4, -2 or +0.
  • The main program reads results with the prompt Result: until an empty line, then prints the table.

For example:

Result: Lions 2-0 Tigers
Result: Tigers 1-1 Red Stars
Result: Red Stars 3-1 Lions
Result: Tigers 2-1 Lions
Result:
Pos Team       P  W  D  L  GF  GA  GD Pts
  1 Red Stars  2  1  1  0   4   2  +2   4
  2 Tigers     3  1  1  1   3   4  -1   4
  3 Lions      3  1  0  2   4   5  -1   3

You haven’t met dictionaries yet, so you’ll need another way to find a team’s running totals. A list of lists, one per team, with a function that finds (or adds) a team’s row, works well.

The slow part

Every result calls find twice, and find looks through every team until it finds the right one. With 20 teams that’s fine. With 20,000 players in a ranking system it’s painfully slow, and the code that searches for a name is clutter. Next week’s dictionaries look up a name in one step, however many there are, and find disappears.

Forge bonus: the referee

Exercise30 points
Forge bonus: the referee

A noughts and crosses board of any size n is a list of n strings, each n characters long, using X, O and . for an empty square. A player wins by filling a whole row, column or diagonal.

  1. Write lines(board) that returns a list of every line on the board as a string: all rows (top to bottom), then all columns (left to right), then the diagonal from top left, then the diagonal from top right. For a 3 by 3 board that’s 8 lines.
  2. Write winner(board) that returns "X" or "O" if that player has a full line, and None if nobody does.
  3. Write status(board) that returns "X wins", "O wins", "Draw" (no winner and no empty squares) or whose turn it is: "X to play" or "O to play". X always goes first, so it’s X’s turn when both players have played the same number of times.
board = ["XOX",
         ".XO",
         "..X"]
status(board)  ->  "X wins"
