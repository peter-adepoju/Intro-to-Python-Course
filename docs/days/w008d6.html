Mixed review

Exercise10 points
Class statistics

Write summary(marks) that returns four values for a non-empty list of marks: the mean (rounded to 1 place), the median, the highest, and how many are at or above the mean. The median of an even-length list is the average of the two middle values. Don’t change the caller’s list.

Exercise10 points
Flatten

Write flatten(groups) that takes a list of lists and returns one list with all their items, in order. flatten([[1, 2], [], [3]]) is [1, 2, 3].

Exercise10 points
Interleave

Write interleave(a, b) that returns a new list taking items alternately from a and b, starting with a. When one runs out, the rest of the other follows. interleave([1, 2, 3], ["x"]) is [1, "x", 2, 3].

Exercise10 points
Reverse Polish

In Reverse Polish notation, operators come after their numbers: 3 4 + means 3 + 4, and 5 1 2 + 4 * + 3 - means 5 + (1 + 2) × 4 − 3. It’s evaluated with a stack: push numbers; on an operator, pop two numbers, apply it, and push the result. Write rpn(expression) for +, - and * with whole numbers, returning the final number.

Forge: the receipt maker, rebuilt

Look back at your Week 5 receipt maker. It split the order twice: once to check every item and measure the names, once to print. Now each item can be read once into a list, and everything else works from the list.

Exercise50 points
Forge: the receipt maker, rebuilt

Write the same receipt maker as in Week 5, built from these functions:

  • parse_order(line) returns a list of items, each a list [name, quantity, price] (name stripped and in title case, quantity an int, price a float), skipping empty items. If any item can’t be read, it returns the text of that item (stripped) instead of a list.
  • receipt(items) returns the whole receipt as one string (lines joined with "\n"), exactly as in Week 5: the item column as wide as the longest name or Item, then Qty in 4, Price and Total in 11, dashed lines as wide as the table, then Subtotal, VAT 7.5% and TOTAL.
  • The main program asks Order: and prints either the receipt or Can't read: and the bad item.

The format of an item is name x quantity @ price, as before. For example:

Order: Rice (5kg) x 2 @ 8500; bread x1@950
Item          Qty      Price      Total
---------------------------------------
Rice (5Kg)      2   8,500.00  17,000.00
Bread           1     950.00     950.00
---------------------------------------
Subtotal                      17,950.00
VAT 7.5%                       1,346.25
TOTAL                         19,296.25
Compare the two versions

Put your Week 5 receipt maker next to this one. The parsing happens once. receipt doesn’t know or care where the items came from: they could come from a file, a web form or a test, and it would work the same. Separating reading data from using it is one of the most important design habits, and lists are what make it possible.

The main program used isinstance(order, str) to ask “is this a string?”. Returning two different kinds of value from one function works, but it’s a little awkward. In Week 11 you’ll learn the proper tool for “this went wrong”: raising an exception.

Forge bonus: shuffling fairly

Exercise30 points
Forge bonus: the Fisher-Yates shuffle

How do you shuffle a list so that every possible order is equally likely? Many people’s first idea (swap every item with a random position anywhere) is subtly unfair. The correct method, the Fisher-Yates shuffle, works backwards:

for i from the last position down to 1:
    pick a random j from 0 to i (including i)
    swap the items at i and j
  1. Write shuffle(items) that shuffles the list in place this way, using random.randint(0, i) for each j, and returns None.
  2. Write shuffled(items) that returns a shuffled copy and leaves the original alone, by copying and then calling shuffle.
  3. Write deal(n_players, n_cards) that makes a deck list(range(1, 53)), shuffles it, and returns a list of n_players hands, each a list of n_cards cards dealt from the top of the deck (the last item), one card to each player in turn.

The checks fix the random numbers, so your shuffle must call random.randint exactly as described: once for each i from len(items) - 1 down to 1.

Python’s own random.shuffle uses exactly this algorithm. Now you know what it does.
