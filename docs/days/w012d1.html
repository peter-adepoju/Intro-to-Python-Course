How to review

Rereading your notes feels productive, but it mostly creates a feeling of familiarity, not the ability to use what you read. What actually works is retrieval practice: trying to recall or use something before you look at it. Getting it wrong and then checking is part of how it works.

So today, for every section:

  1. Try each prediction before running it, and write your guess down.
  2. If you get one wrong, work out exactly why before moving on.
  3. Keep a list of anything that surprised you. That list is your revision plan for the exam.

Values, types and strings

Week 1’s ideas in brief: every value has a type (int, float, str, bool); operators behave differently for different types; a variable is a name for a value, and assignment moves the name; strings are sequences you can index and slice; input always gives a string.

Key idea

/ always gives a float; // rounds down (towards minus infinity, so -7 // 2 is -4). Floats are approximate, so compare them with round or a tolerance. Assignment never links two names: y = x copies the reference, and rebinding x later doesn’t touch y.

Decisions

Week 2: comparisons give booleans; and, or and not combine them; if, elif and else choose one branch, checked from the top.

Key idea

and binds tighter than or. In an elif chain only the first true branch runs, so put the most specific test first. and and or short-circuit: the right side isn’t evaluated if the left side already decides the answer, which is why x == 0 or 1 / x > 2 doesn’t crash. Empty things and zero are false; everything else is true, including "0".

Loops

Weeks 3 and 4: while repeats while a condition is true; for goes through a sequence; range(start, stop, step) stops before stop; break leaves a loop, continue skips to the next round; nested loops run the inner loop completely for each round of the outer one.

Key idea

Every loop needs a reason to stop. With while, something in the body must change the condition. Off-by-one errors live in range’s stop value and in < versus <=: test the smallest cases (0, 1 and 2 items) by hand.

Practice

Use anything you know: functions, lists, dictionaries. The skills from Weeks 1 to 4 are what’s being practised, but you don’t have to solve these the way you would have in Week 2.

Exercise10 points
Change from a note

Write change(paid, cost) that returns the change in the fewest notes and coins, as a dictionary from denomination to how many, using naira denominations 1000, 500, 200, 100, 50, 20, 10, 5 and 1. Leave out denominations not used. Raise a ValueError if paid is less than cost.

Exercise10 points
Leap years

Write is_leap(year): divisible by 4, except years divisible by 100, which are leap years only if they’re divisible by 400. Then print the leap years from 1896 to 1912 (inclusive) on one line, separated by spaces.

Exercise10 points
Grade boundaries

Write grade(mark) returning "A" for 70 to 100, "B" for 60 to 69, "C" for 50 to 59, "D" for 45 to 49, "E" for 40 to 44 and "F" below 40. Raise a ValueError for a mark outside 0 to 100.

Exercise10 points
Digit sum, the long way

Without turning the number into a string, write digit_sum(n) that adds up the digits of a whole number, using % and // in a while loop. Negative numbers use their digits too.

Exercise10 points
A number triangle

Write triangle(n) that returns, as one string with lines joined by "\n", a triangle of n rows where row r (from 1) holds the numbers 1 to r separated by spaces, centred in the width of the last row.

Exercise15 points
Guess the number

Write a guessing game. The secret number is random.randint(1, 100). Ask Guess: until the guess is right, replying Too low, Too high, or, for something that isn’t a whole number, Whole numbers only (which doesn’t count as a guess). At the end print Got it in N guesses (or 1 guess).

Exercise10 points
Primes below n

Write primes_below(n) that returns a list of the primes less than n, testing each number with trial division up to its square root.

Exercise25 points
Challenge: Roman numerals

Write to_roman(n) for 1 to 3999 (raise a ValueError otherwise), and from_roman(text) that converts back, raising a ValueError for anything that isn’t the standard way of writing a number (so "IIII", "VX" and "ABC" are rejected). The standard form uses M D C L X V I with subtractive pairs CM CD XC XL IX IV.

to_roman(2026)       ->  "MMXXVI"
from_roman("XLII")   ->  42
