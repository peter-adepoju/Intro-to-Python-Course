Forge

This week was about method: understand the problem, plan it, split it into pieces, recognise the patterns, check the edges. Today’s Forge is a chance to use all of it on something with real subtlety: the scoring and solving logic of the word game Wordle, where repeated letters trip up almost everyone’s first attempt. The bonus teaches the computer to play Bulls and Cows by itself. The weekly quiz and review finish the week.

By the end of today you can

  • Pin down a subtle rule with worked examples before coding it
  • Decompose a game’s logic into small functions you can check separately
  • Combine patterns (frequency maps, filters, best so far) into a solver
  • Check your solution against the awkward cases on purpose

Mixed review

Exercise10 points
Rotate a list

Write rotate(items, k) that returns a new list rotated k places to the right: rotate([1, 2, 3, 4, 5], 2) is [4, 5, 1, 2, 3]. k can be larger than the list or negative (rotating left). An empty list gives []. Work out the edge cases before you code.

Exercise10 points
Peaks

A peak is a value bigger than both its neighbours; the first and last values count as peaks if they’re bigger than their one neighbour. Write peaks(values) that returns the positions of the peaks. A list of one value has a peak at 0; an empty list has none.

Exercise10 points
Balance point

Write balance_index(values) that returns the first position where the sum of the items to its left equals the sum of the items to its right (the item itself counts on neither side), or -1. Use a running total so you go through the list only once or twice.

Exercise10 points
Compress ranges

Write ranges(numbers) that takes a sorted list of different whole numbers and describes it compactly: [1, 2, 3, 5, 7, 8, 9, 10] gives "1-3,5,7-10". A run of two, like [4, 5], is written "4-5".

Forge: Wordle

In Wordle, you guess a five-letter word. Each letter of your guess is marked green if it’s in the answer in that position, yellow if it’s in the answer but somewhere else, and grey if it isn’t in the answer. That sounds simple until letters repeat. Try these by hand before reading on (we’ll write green as G, yellow as Y, grey as .):

Answer Guess Feedback
crane react YYGY.
crane nanny .Y.G.
abbey babes YYGG.
speed erase Y..YY

Look at nanny: the answer has one n, and it’s matched green by the fourth letter. So the first and third ns are grey, not yellow: a letter can only be marked as many times as it appears in the answer, and greens claim their letters first. That’s the rule people get wrong.

Exercise50 points
Forge: Wordle

Write the logic of Wordle and a simple solver, using the word list in words.txt (one five-letter word per line).

  1. feedback(answer, guess): the five-character feedback string, following the rules above exactly: first mark greens; then, going left to right, mark a letter yellow only if the answer still has an unmatched copy of it.
  2. load_words(path): the words in the file, stripped, lower case, as a list.
  3. consistent(word, guess, fb): whether word could be the answer, given that guess received the feedback fb. (Hint: there’s a one-line answer using feedback.)
  4. remaining(words, history): the words consistent with every (guess, feedback) pair in history, in their original order.
  5. best_guess(candidates): the candidate that covers the most common letters. For each letter, count how many candidates contain it at least once; a word’s score is the sum of those counts over its different letters. Return the highest-scoring word, the alphabetically first if tied.

The method at work

Look at what made this manageable. Understanding came first: the four worked examples pinned down the repeated-letter rule before any code. Decomposition turned “write Wordle” into five functions, each checkable. Patterns did the rest: a frequency map for unmatched letters, a filter for remaining, a best-so-far for best_guess. And consistent is one line, because it reuses feedback instead of re-deriving the rules: the cleverest step of the whole solution, and the kind of idea you only see once the pieces are clear.

Forge bonus: a Bulls and Cows solver

On Day 4 you built Bulls and Cows for a human to play. Now the computer plays. The same idea as the Wordle solver works: keep a list of every secret that’s still possible, guess one of them, and keep only the secrets that would have given the same feedback.

Exercise30 points
Forge bonus: a Bulls and Cows solver

Write:

  • all_secrets(): every string of 4 different digits, in increasing order ("0123" first, "9876" last). There are 5,040.
  • score(secret, guess): (bulls, cows), as on Day 4.
  • solve(secret): plays a whole game against secret, and returns the list of guesses made, ending with the secret. Each guess is the first candidate still possible; after each guess, keep only the candidates that would give the same score for that guess.

Most secrets fall in 7 guesses or fewer this way.
