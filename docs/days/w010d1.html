Dictionaries: keys and values

Last week’s league table had to search through every team to find the one it wanted. A dictionary does that lookup in one step: you give it a key, such as a team’s name, and it gives back the value stored with it. Dictionaries are probably the most used data structure in Python, and today you’ll learn how they work.

By the end of today you can

  • Make a dictionary, look up a value by its key, and explain a KeyError
  • Add, change and remove entries, and check whether a key is present with in
  • Look up a key safely with get and a default
  • Loop over keys, values and key-value pairs
  • Say which values can be keys, and why lookups are fast

Keys and values

A dictionary stores entries, each a key and the value that goes with it. Write it in curly brackets, with a colon between each key and its value:

You look a value up by putting its key in square brackets, just as you put an index in square brackets for a list. The difference is that the key can be a name, a word, or anything else suitable, not just a position.

Think of a real dictionary: you look up a word (the key) and find its meaning (the value). Or a phone’s contact list: a name and a number.

Tip

Use d[key] when the key must be there, so that a mistake shows up as a KeyError straight away. Use d.get(key, default) when a missing key is normal and you know what it should mean.

Common mistake

Don’t add or remove keys while you loop over a dictionary: Python raises RuntimeError: dictionary changed size during iteration. Changing the values of existing keys is fine. To remove entries, loop over list(d), a copy of the keys.

What can be a key

Values can be anything: numbers, strings, lists, even other dictionaries. Keys are stricter. A key must be immutable: strings, numbers, booleans and tuples (of immutable things) work; lists and dictionaries don’t.

Why? The reason is also why lookups are fast. Python doesn’t search through the keys one by one. It turns the key into a number called its hash, and uses that number to go straight to the place where the entry is stored, like going straight to the right page in a paper dictionary. If a key could change after it was stored, its hash would change, and Python would look in the wrong place. So keys must be values that can’t change: Python calls them hashable.

(The numbers themselves change each time Python starts, for security, so we only compare them.)

Key idea

Finding a key in a dictionary takes about the same time whether it has ten entries or ten million. Finding an item in a list means looking through it. That difference is why dictionaries are everywhere.
